# 字段映射、实例关联与发布修订

日期：2026-11-04。本文汇总本轮讨论并规定当前实现方向。它补充《按用户目标自主构图》，取代其中“发布前重新查询所有数据库映射”的要求。真实客户数据只由用户提供运行反馈；本地复现使用测试数据，不能作为客户语义验收。

## 已确认的问题

- 查询额度统计包含文件内部查询、数据库元数据和事务控制，运行报告却主要统计数据查询。240 次不是 240 次 Agent 探查。
- 发布前重新执行整个草稿，预算耗尽等执行失败被统一误报为 `construction_source_changed`。
- 同一草稿修订的验证预览文件会被失败重验覆盖；原有效图没有独立保存。
- 预算终止异常被包装成“修改请求后重试”，Harness 不知道查询已不可能成功。
- 结构映射的检查和完整实例生成绑定，无法先交付可执行的图谱结构。
- 关系映射只能从同一物理行读取端点。探索 SQL 能做 JOIN，不代表保存的映射能执行 JOIN。
- 校验只检查目标节点是否存在于图中，未表达“必须在指定目标表中找到匹配记录”。
- 名称只放在展示字段时会生成模板标签，不参与主名称一致性检查；英文名称也不会自动成为别名。

## 目标与不变量

用户目标决定对象、关系、实例范围及语言。Agent 发现字段角色和映射；程序负责授权读取、实际匹配、身份与证据计算。不得硬编码行业、L1/L2、CODE/CN_NAME 等物理命名。

同一对象按已确认的身份键合并，物理层位不自动进入身份。重复出现增加来源支持。层级任务保留位置和完整行上下文，避免把不同记录中的边拼成从未出现过的来源路径。连续同码是否填充由材料和数据判断。

源库连接和本地文件接入方式保持兼容。只读 SQL 守卫、列权限、取消、单次超时、总运行时间和内存限制继续执行。源数据、历史运行和有效成果不会在任务结束时自动清理。

## 构建分成结构检查和实例执行

`validate_graph_draft(mode="structure")` 检查实体与关系定义、身份键、字段存在性、访问范围、筛选和连接参数，保存 YAML 结构检查产物，不执行事实数据查询。结构通过只说明映射符合当前目录和静态契约，不保证数据库执行、所有实例约束或业务语义通过。

未显式传入 mode 时采用项目 `construction_target`（默认 `instances`）；`mode="instances"` 执行草稿指定范围内的完整必要投影，生成具体节点、边和来源支持。现有 `predicate` 表达按组织、期间等范围构建；结果必须标明实际范围。抽样、结构检查和完整实例检查不能互相替代。

结构成果有独立版本和发布入口参数，不计为实例节点，不将“尚未实例化”写成“完整业务图已生成”。用户要求完整实例时，结构产物不能冒充目标完成。按需实例化以保存的映射和显式范围为输入；画布直接查询活库属于后续产品能力，本轮不将已有两跳图读取误称为虚拟图查询。

## 关系的实际配对

保留同一行 `source_key_columns` / `target_key_columns` 的直接配对。新增可选 `source_lookup` / `target_lookup`：指定授权来源、表、`match_columns`、解析出的 `key_columns` 及筛选。对应端的本行键列作为查找值，匹配目标记录后才取得最终端点身份。

查找可跨表、跨来源或指向同一表，实现外键核验、身份转换和等值自连接。默认每个输入值只能匹配一个不同身份，缺失或歧义给出明确诊断；合法多对多必须显式选择多匹配。不同端点组合只能来自原行配对及其匹配结果，不能将两列独立 DISTINCT 集合相乘。

指定查找来源就是端点来源约束：即使全图已有同编码节点，也不能替代目标表实际匹配。支持记录包含查找来源、匹配列、实际端点键及各来源的可见范围。没有双方授权时不能通过同名节点或别的来源间接暴露关联。

执行器先提供有界、完整的必要列查找，复用同一次执行快照内的相同投影；不进行无界全列笛卡尔扫描，不自动创建源库视图。两亿行上聚合可能扫描大量输入，输出 LIMIT 不构成扫描量保证。跨来源键采用带类型的精确匹配，不会把文本 `"1"`、数字 `1` 自动视为同一键；类型差异须先明确统一口径。任意不等值、时间窗口或多段派生 JOIN 暂不伪装成已支持的等值查找；无法表达时记录明确缺口。

## 查询预算与停止条件

`max_db_queries: null` 表示不限制查询次数；正整数表示总次数上限，0 和负数无效。前端提供“不限次数”与自定义上限，保存、刷新、启动配置一致。次数不限不改变其他资源限制。

分别报告实际预算计数和数据查询计数，解释控制语句与元数据消耗。用完硬额度后返回不可重试的资源状态，停止新的源查询。允许有限收尾，读取工作区并发布已经完整验证的产物；不能无限重复探查、校验或改写草稿。到限记录原始原因，不改报源数据变化。

## 不可变验证产物与发布

每次校验保存独立验证编号、修订、配置/权限指纹、起止时间、范围、检查结果和产物摘要。最近一次尝试与最近一次成功分别记录；失败不得覆盖成功图。

发布的是指定验证时点得到的固定产物。默认发布最近一次通过的适用验证；如果后续数据检查发现矛盾，不能静默回退，需明确选择历史成功验证。查询额度或传输失败不推翻历史时点的有效快照。

发布核对草稿修订、授权、原始文件/文档适用性和产物摘要，执行已发布图之间的身份及依赖检查。数据库不在发布时重新执行全草稿；记录各来源为独立读取快照，不宣称混合来源具备分布式同时点一致性。刷新数据库结果是新的一次实例执行，不修改旧产物。

## 主名称、别名与画布

skill 与 schema 明确区分 `key_columns`（身份）、`label_column`（主名称）、`alias_columns`（经确认的其他名称）和 `display_columns`（补充展示或无独立名称对象的组合显示）。已有可靠名称时应作为主名称；不能仅为绕过名称冲突把它降为展示组件。

验证返回映射级名称质量提示及现有 `label_origins` 统计。提示不阻断合法无名称对象，也不独立导致整轮 PARTIAL。提示必须说明影响和修订字段，不凭固定列名自动改写身份或名称。

画布主名称优先，编码作为辅助信息；长标签按宽度换行和省略，详情保留完整值。前端不得根据 `cn_name` 等任意字段名猜测并覆盖源名称。历史图需要修订映射并生成新版本，不直接篡改已发布摘要。

## 验收与实施记录

本轮先完成设计，再实现与验证。完成情况记录到 IMPLEMENTATION_STATUS；以下场景是工程验收，不代表真实模型或客户环境通过：

1. 不限次数和有限次数配置能保存、刷新、传入所有来源；有限额度仍正确阻止新增查询。
2. 数据未变化而额度耗尽时返回预算原因；最多有限收尾调用；已有成功产物仍在。
3. 校验后发布不再发起数据库事实查询；失败重验不覆盖旧图；修改草稿或篡改产物仍不能发布。
4. 结构检查零事实查询；结构 YAML 可恢复，实例完整性不被虚假标记为通过。
5. 订单通过邮箱匹配客户编号、同表自连接、跨源连接、目标缺失、歧义和权限隔离。
6. 同指标跨层位一个节点，边保留各行路径支持，填充处理不丢实体支持。
7. 主名称和别名角色明确，模板兜底有可操作提示，正常无名称对象不被强制拒绝。
8. 前后端回归、构建和本地交互检查；真实 Gauss 大表与真实模型发现另行验收。
