# 探索超时后的提交与请求消重

> 设计状态（2026-11-03）：本页保留原版本的方案、故障与验证记录。当前通用构图目标、Harness 迁移与 YAML 产物规范见 [按用户目标自主构图](GENERIC_GRAPH_CONSTRUCTION.md)。本文的历史通过结果不证明新路径已验收；未被迁移改变的接入、执行、权限及平台约束继续适用。

## 故障归因

用户提供的远端轨迹显示，前 11 次请求成功，第 12 步等待 600.05 秒后读超时，相同请求又用约 138.86 秒剩余时间重试，最终耗尽本表预算。无法访问远端原始数据或轨迹，因此这些数字来自用户反馈；以下机制已从本地代码复现。

总时限 1,800 秒时，对象发现阶段只有 `1800 × 0.75 × 0.65 = 877.5` 秒。根据给出的总耗时，600 秒的尝试开始时运行约过了 138 秒，结束时才约过了 738 秒。随后原样重试又耗尽余量。框架原先主要靠最后两轮触发提交，不能及时应对单轮变慢。

`read_timeout` 证明等待响应期间发生了读超时，不能独立证明时间都花在模型推理上。网关排队、缓冲、网络和推理都可能参与。多轮累计 input tokens 也不能视为最后一次请求长度。

AgentScope 提供循环和工具执行；本项目负责上下文投影、工具与提交协议、预算调度和重试。这些封装设计存在实际缺口，模型在其他 Agent 中可正常使用，并不能替本项目的运行方式背书。

## 本轮代码行为

1. **原样重试先检查时间。** `read_timeout` 后，如果阶段剩余时间明显短于刚失败的尝试耗时，则跳过原样重放。保留 `model_transport_error`，记录 `model_retry_skipped`、剩余时间和跳过原因。HTTP 的空闲读取超时与整个流的耗时分开处理；不能因长流持续输出超过配置的空闲超时，就错误禁止重试。正常连接错误和协议修复仍遵守原有重试额度。
2. **按观察到的耗时提前进入提交。** Agent 使用最近三个成功请求中最长耗时的两倍，估计一次提交及一次反馈所需时间。当剩余时间小于该估计时，提供本地提交工具并说明剩余时间，不再继续源数据探索。这个估计帮助调度，不保证后续请求一定完成，不延长阶段时限或增加模型调用额度。
3. **超时后最多一次转为提交。** 如果探索请求的原样重试因时间不足被跳过，且仍有本任务的轮数、提交额度和时间，则使用提交工具集合发起新一轮，只提交已有发现或明确未决。失败响应中的半截工具不会执行。提交阶段自身再超时，不得借此反复重开恢复回合。
4. **消除完全相同的上下文副本。** 工具结果的文档、文档引用、表范围与固定输入完全相等时，改为指向 `input` 的引用。比较保留标量类型、列表顺序、范围、文档版本和读取状态；任何差异都保留原文。该投影不改原始记录、行值、工具参数、校验反馈或证据状态。之后裁剪工具历史，也不会丢失引用目标。

新增轨迹分别记录时间收束、超时后提交、重试跳过和上下文复用。原始模型请求、响应及工具记录继续保留。既有输入/输出硬限制、累计 token 配置及探索轮数配置独立生效。

表中的估算与实际值不能混用。消重后仍未达到 32K 估算目标：系统提示约 4K、工具 schemas 约 15K–17K，固定用户输入约 10K–20K，还需保留草稿及错误反馈。本轮没有删掉校验约束来制造较小数字，也没有用单次模型计量校准所有模型的 tokenizer。

后续若要进一步缩小固定输入，需要按任务阶段选择工具、改进提案协议，并在相同输入上比较有效提交、通过验证的规则、单次实际输入、调用数和耗时。直接换成 Hermes 不会自动消除传给它的冗长工具 schema 或项目自身的阶段预算问题；相关接口与适配成本见 [Hermes 评估](HERMES_CONTEXT_REVIEW_20261103.md)。

## 验证与实验隔离

离线回归覆盖 600 秒超时后约 139 秒余量：跳过相同请求，转入提交，产生并保留合法草稿；同时覆盖正常快速任务继续探索、提前时间收束、直接与 SDK 包装的读超时、长流重试、真正的预算耗尽、配置关闭重试、连接错误和 JSON/schema 修复。模型调用和 reservation 均保持原计账边界。

这些测试证明运行控制可以完成该故障场景，不能代替真实数据的语义验收。当前实验仍从冻结工作树运行 `4734882`；本轮没有重启服务、覆盖其代码或影响实验结果。

本地验证：后端全套 2,607 项通过（150.96 秒），前端 234 项通过，类型检查及生产构建通过。日志分别为 `/tmp/ict-runtime-recovery-final-backend-20261103.log`、`/tmp/ict-runtime-recovery-frontend-20261103.log`、`/tmp/ict-runtime-recovery-build-20261103.log`。全量回归还发现并修正了新增动态时间字段导致的首轮预检与实际请求大小不一致；时间字段现在只在改变提交策略时附带。
