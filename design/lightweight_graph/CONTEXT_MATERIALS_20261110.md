# 工具结果与 Agent 上下文管理

## 问题与范围

当前基线为 `32bb0a1`。累计返回量统计程序从来源读取的数据，不等于模型输入量。实例验证在 Python 内部处理完整投影，返回统计与诊断；探查工具才把少量样例交给模型。提高 `max_returned_bytes` 不能解决模型历史重复携带样例、大草稿和诊断的问题。

本地 Harness 已装配原生工具结果裁剪、摘要压缩和会话检索。原生裁剪在压力达到阈值后执行，通用策略保留文本头尾；旧会话的完整事件读取又可能重新带回大内容。一次成功保存的草稿 YAML 也会作为历史工具参数反复进入模型请求。仅增加输入容量会延后问题，不能消除这些重复内容。

本轮补充工具结果的可恢复摘要和每轮派发前的历史整理。继续使用现有 Harness 的 Agent 循环、会话事件、token 计量和压缩服务；不新增第二套推理循环，不修改抽取身份规则。

## 数据路径

1. 来源查询、实例验证仍按原授权、完整性和资源限制执行。完整投影仍供执行器使用，累计返回量与工作内存分别计量。
2. 工具执行产生的完整回复保留。超出单份工具结果的上下文额度时，保存到本地当前会话的结果材料，返回状态、必要诊断、完整性说明、摘要和材料引用。保存或发布不因展示裁剪重新执行。
3. Agent 通过 `read_material(name="result:<id>", page=0, section="/data/rows")` 按需要读取。`section` 是 JSON pointer；不填写时读取整份材料的页面。读取已保存材料不执行 SQL，不改变原查询范围和证据。
4. 旧工具结果及已执行的大草稿输入在原生会话表面转成短记录，保留执行结果和恢复位置。原始事件仍可排查；未执行调用、真实用户输入和原始任务不随之删除。历史大事件通过有界分页读取，避免一次重新载入全文。
5. 多轮短结果仍会累积，由 Harness 原生摘要压缩处理。摘要保留目标覆盖、已保存修订、证据引用和下一步，目标与 skill 单独固定。最终模型请求仍受配置输入上限检查。

## 计量、完整性与权限

工具结果及材料页面用现有中英文混合文本估算器计量，包含 JSON 包装与转义开销。原生会话整理和整次模型请求使用 Harness 的 token meter；它以字符数估算并用服务商 usage 校准，不是精确分词器。两处估算不一致时，派发前仍会再次限制历史内容。字符与字节还用于文件、内存和传输保护，其限额不冒充上下文容量。

一般工具回复默认最多约 4,096 个估算 tokens；输入容量或工作窗口更小时会进一步缩小。这个额度覆盖整个回复，而不只是其中的数据字段。已完成的一组大工具调用也共用一个历史摘要上限，避免多个小结果合起来再次撑大上下文。必要的恢复说明都放不下时会明确报错，不偷偷提高用户设置的输入上限。

来源完整性和展示完整性分别记录。查询原本截断的结果，存成文件以后仍然截断；当前页读完不意味着整份文档或全表读完。统计、错误和验证结论不能因为裁剪变成通过，材料引用也不增加证据权限。模型应只读当前问题需要的部分，不逐页复制全文进摘要。

结果文件只保存工具已经返回的内容，不额外把数据库整表下载到本地。使用当前会话、上下文和访问范围绑定，拒绝任意路径与旧权限引用。运行结束不自动删除文件，仍可供人工排查；`result_ref` 只在签发它的工具会话内有效，Worker 重启或新运行不能直接沿用。新运行通过已有入口读取草稿和验证材料，需要事实数据时重新查询。它是上下文按需读取机制，不是完整投影的磁盘缓存或跨运行事实缓存。

整理历史使用原生追加事件和上下文替换，不改写原事件。图谱工具的完整回复保存在结果材料中，原生工具轨迹记录实际返回给内核的摘要与引用，模型请求轨迹记录实际发出的内容。前端把整理历史产生的工作记录归为“历史结果压缩”，不显示为新的人类指令或第二次工具执行。`session_event_read_page` 按原生会话读取权限访问原事件，再把选定片段交给模型；它控制模型输入量，不意味着历史文件读取本身改成了流式解析。

## 验证标准

- 大目录、宽样例、草稿及多条诊断不直接撑大模型回复；需要的信息可从结果引用恢复，原内容摘要可核对。
- 页面与嵌套字段有界，中文与巨型单元格不会绕过额度；读取不会重新发起数据库查询。
- 裁剪保留失败状态、来源截断标记和材料版本；错误与已执行写入不会因结果展示失败重放。
- 真实原生 Harness 配本地脚本模型验证最终请求，覆盖连续工具调用、历史事件重读、大草稿输入、原始目标保留及原事件可追溯。
- 回归仍验证只读、取消、完整实例检查和发布边界。通过不代表已验证客户数据库或真实模型自主发现质量。

## 本轮验证结果

最终本地后端回归 3,275 项通过；此前已通过的 310 秒默认 fetch 长测试未重复执行。真实 Harness 连接本地脚本模型的测试确认：20 个大调用各执行一次，后续请求只携带限额内的整组工作记录；原事件可以恢复。实际 HTTP MCP 用例确认按字段和页面读取材料不会再次查询数据库，原查询的截断标记保留。独立复核的 12 条不完整结果在 1,024-token 限额内保留全部状态与材料版本。详见[实施记录](../../IMPLEMENTATION_STATUS.md)。

以上验证不包含客户数据库、外部模型自主发现效果和 Windows 实机；Windows 文件访问分支通过能力模拟测试。原生历史与材料文件仍占用本地存储，由用户主动清理。
