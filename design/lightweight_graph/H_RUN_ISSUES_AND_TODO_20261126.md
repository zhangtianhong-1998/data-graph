## 三、源码确认的问题

### 1. 身份验证、数据授权和业务适用范围混在同一拒绝链中

`src/lightgraph/construction/access.py:36` 的指纹覆盖整单元选表、选列、范围、文档范围和目标约束等内容。它适合核对某份输入或授权配置是否改变，不适合作为两个不同分支拥有合法融合权限的充分或必要判据。

`projection_proposals.py:494–537` 只有在同物理表的情况下，才允许用 `common_table_grant` 替代整单元指纹相等。不同物理表没有对应通道，即使各方分别持有自己的合法授权，也可能被拒。不能通过给四个分支补写相同指纹、扩大选表范围来绕过它。

此外，`cross_table_identity_unverified` 是优先返回的拒绝码。H 同时记录了 `first_observation_result=unverified_applicability` 和指纹不同；修好共同身份依据后，仍可能遇到范围或授权拒绝。一次只解释最先失败的条件，会继续造成逐关补洞。

### 2. 证据协议对实际业务材料的适配不足

`identity_authority.py:25–52` 已区分字段定位、共享字段证明和目录声明。`tools.py:552–565` 存在生产写入路径，`test_publication_identity_authority.py:417–479` 也已覆盖独立文档经真实写入后形成共同目录证明的正例，不能继续声称“完全没有 writer 路径测试”。

不过该正例仍预期两单元授权指纹一致，没有覆盖本项目正常的分表授权。`documents/identity_contract.py:52–68` 的自然语言兼容路径只识别少量英文句式；普通中文业务说明无法识别时，不能一律归因于业务没有资料。

实体合同存在缺字段、字段声明不一致和真实语义冲突三种情况。它们都可能生成不同 `__def_` 变体，但不应得到同一种不可再审的处理。类型名不同不能直接证明实体不同；同码同名也不能自动消除计量口径、独立编号域等真实冲突。

### 3. 项目模型配置被审查模块再次缩小

`runtime/config.py:81` 的 `max_output_tokens` 是单次输出配置；抽取侧 `construction/runner.py:38–40` 将其传给 Harness。合并审查 `overlap_review.py:382–396` 则重新取上限 8,192／16,384，并在第 418 行写入实际请求。第 306 行附近另有 64KB 请求限制，第 383 行另有最多 128KB 响应限制。

`test_overlap_pattern_model.py:428` 目前把“项目配置 50,000，实际仍只能请求 8,192／16,384 后回退”作为期望。这类测试需要随预算契约修订，不能继续用它证明行为合理。

H 现场的生效配置没有随报告提供，不能将当前默认 65,536 写成现场配置。项目还可能通过 `agent_config` 使用独立配置，诊断必须检查 `resolved_model`。项目历史字段 `max_tokens` 与 HTTP 请求参数同名但含义不同，也需明确区分。

### 4. 关系范围与行见证的生产、判定存在缺口

`contexts.py:114–143` 支持常量维度、列维度、显式 global 及 unknown；`models.py:53–55` 允许省略范围，省略后是 unknown。严格对账却要求范围已知，二者之间缺少及时发现、补证和明确报告的流程。

`relation_assertions.py:32–46` 主要识别工作表快照行及物理列，排除部分 lookup、继承和元数据端点路径。`scripts/fusion_edge_comparison.py:153` 将统计口径标为 `committed_qualified_worksheet_observations`，不能作为所有数据库和跨表关系的唯一质量判据。

行见证还可能被执行器降级：`executor.py:132–146` 只在来源提供工作表快照时收集；第 286–309 行在内存超限后删除已收集的见证并停止收集。应区分来源不支持、旧格式缺失、预算降级、数据损坏和草稿遗漏。

## 五、执行顺序与是否现在重抽

| 阶段 | 可以并行的工作 | 是否需要重新抽取 |
|---|---|---|
| 先修可复现的产品问题 | 跨表授权与身份路径；模型预算与裁决协议；关系范围与评估口径 | 不需要。用现有模式卡、代码及代表性合成输入验证 |
| 验证生产成功路径 | 正常中文材料、分表授权、独立文档→Agent 草稿→证据写入→合并；同时跑反例 | 需要小规模真实抽取，必须走正常入口，不能注入证明标记 |
| 固定干净基线 | 核对来源、配置、版本及运行空间 | 不需要模型调用 |
| 一次系统实验 | 四分支新抽取；冻结后做确定性／Agent 合并对照和隔离查询 | 需要一次完整新抽取，随后复用这次的新检查点 |

结论是**需要完整重抽，但不应现在按原代码再跑一次**。先让正常宽表输入存在可达、经验证的融合路径，再通过干净实验检验全链路。旧检查点仍适合复现预算、协议、验证器和历史对账问题，不足以验收新的抽取证据生产能力。
