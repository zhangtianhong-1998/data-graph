# 多表探索请求超限：原因与修复

本轮 `runs/full-extraction-v2-20261030T015515Z` 在 356 秒后以 PARTIAL 结束，18 次模型调用、617,587 tokens，五表均报 `model_packet_too_large`，未产生业务规则和节点。调用次数和运行时限均未耗尽；累计 token 上限已经取消。

## 为什么旧实验没有触发

旧、新实验的单请求上限都是 262,144 字节。旧实验只有一张表，新实验有五张表；单任务额度由 12 回合 / 24 次来源工具调用增加至 20 回合 / 48 次。冻结代码的离线测量如下：

| 项目 | 旧实验 | 新实验 |
| --- | ---: | ---: |
| 层级任务首请求 | 55,307 B | 63,204 B |
| 提案工具 schema | 22,112 B | 25,238 B |
| 层级 metadata_digest | 3,301 B | 3,301 B |

新版其余四表首请求为 59,837 / 54,867 / 54,881 / 54,791 字节，均未超限。初始包变大不是主要原因，也没有把工作簿全量行直接塞进请求。

旧、新代码都存在以下问题：

1. `search_knowledge(table)` 对累计访问过的所有表的文档分页。查一张表，也会带回其他表的文档；访问新表还会改变原查询的分页。
2. 同一文档同时存在于任务输入、调用上下文和工具响应的附带上下文中。知识查询又在 `data.sections` 返回一份。
3. 首轮只按包大小裁剪目录，后续全量保留工具调用历史。单条工具结果合法，不代表它们累积后的下一次请求仍合法。
4. 首轮目录选择可以用尽包空间，没有为后续工具结果预留余量。

这些问题在单表短路径中没有触发限制，多表和更长探索把它们暴露出来。取消累计 token 上限不会直接改变单次请求大小。

## 同输入离线复现

依次读取五表 metadata，再读取四张表的 knowledge，共九次不同的合法工具调用。使用冻结代码时，下一请求为 **268,975 B**，超过 256 KiB；当前修复后为 **147,585 B**，减少 **45.1%**，尚未使用历史裁剪。

激活五表后，原知识工具返回 23,909 字节，其中附带上下文占 14,494 字节。原实验的工作内存峰值也为 23,909 字节，但这不能证明模型走了同一条调用路径。

原实验不留存原始对话，console.log 为空，因此上述过程是可复现的触发路径，不是对真实 18 次模型调用的精确回放。

复现命令只读取本地冻结输入，输出计数和字节大小，不访问模型，不输出源值：

```bash
.venv/bin/python examples/measure_discovery_prompt.py runs/full-extraction-v2-20261030T015515Z
.venv/bin/python examples/measure_discovery_prompt.py runs/full-extraction-v2-20261030T015515Z --code src
```

## 代码修改

- `search_knowledge` 按请求的表和列选择文档，再做稳定分页。累计签发的文档引用仍保留，供后续独立复核。
- 预检和实际请求共用任务包构造。文档、样本、迭代上下文只保留一份正文，其他位置使用明确的字段引用。
- Formatter 只复用与当前输入**完全相同**的附带文档。不同版本、不同读取范围和新的知识分页都保留；来源查询结果不改写。只把首个用户消息替换为任务包，其余反馈保留原文。
- 可选目录预留最多 64 KiB、且不超过可用额度 25% 的空间。当前任务表始终保留；固定任务内容本身超限仍明确失败。
- 每轮都测量完整请求。历史导致超限时，在现有调用和回合额度内转为提交阶段，移除来源查询工具；按完整的调用及结果组移除较早的来源历史。最新来源结果、所有本地草稿提交、词表声明及校验反馈保持原样。不会出现悬空的 tool_call_id，也不调用额外模型做摘要。
- 裁剪会明确告知模型哪些历史不在窗口内，不能据此推断“没有证据”。若固定内容、最新结果及必须保留的提交记录仍无法容纳，继续明确拒绝，不删授权条件或放宽语义校验。
- 报告增加压力回合数、移除的历史组数、处理前后字节峰值和拒绝计数，只记录数值。发现版本升级为 `goal_driven_iterations/15`，避免沿用旧发现缓存。

## 验证边界

新增回归覆盖多工具批次完整性、草稿在历史裁剪后正常结束、无额外模型调用、最新证据与字段反馈保留、首轮硬限制、文档精确去重、表列范围及分页稳定性。原失败实验的代码与输入未改动。

完整 Python 回归 **2,061 项通过**（76.61 秒）；之后补充压力阶段“字段错误 → 修正 → 结束”用例，相关三项均通过。两轮旧实验的冻结清单及数据集全部 19 个文件的哈希复核通过；原始对话不写入任何诊断文件。

本次修复已经通过本地复现与工程回归；尚未用真实模型重新验收自动发现效果。预算仍为 240 次调用、累计 tokens 不限、最长 120 分钟，单请求上限仍为 256 KiB。
