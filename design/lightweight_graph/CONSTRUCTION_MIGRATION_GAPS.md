# 新构建流程的迁移范围与未完成项

更新：2026-11-03。

新入口由 DeepSeek Harness 自主选择探查、保存、验证和发布工具，输出通用实体与关系映射的 YAML。旧 `RuleSpec`、固定表级发现阶段、coverage 和关系修订调度不再驱动新入口。本文件记录旧测试应如何处理，以及尚未迁移的保障。本轮保留有价值的旧回归，不用 `skip` 掩盖差距，也不宣称全部功能已经迁移。

## 当前权限边界

数据接入逻辑保持不变：原来源连接、数据库行权限、表列白名单、`scopes` 与 `document_scopes` 继续生效。`scopes` 控制结果可见性，不代替探查阶段的数据库行权限和表列授权。Markdown 目标、知识文档与 Agent 草稿都不能扩大这些授权。

新增顶层 `scope_bindings` 由用户或程序按 `source_id / schema / table / columns` 配置。单列范围使用 `str(value)`，多列使用规范化的列名—值字典，沿用旧 `scope.namespaces` 的编码方式。没有绑定的贡献为 `public`；程序不会从对象身份键、业务 namespace 或“责任中心”等列名推测授权。`public` 只表示授权来源中的默认支持范围，并不表示互联网公开。

新 YAML 图为实体存在、名称、别名、属性及关系分别保留支持。读取时先按当前范围过滤支持，再重建节点和边；同一节点的 A/B 私有属性不会因为节点可见而一起展示。仅切换 `scopes` 不使图失效；隔离域、来源/列授权或 `scope_bindings` 改变时，权限指纹检查拒绝旧图，避免旧缓存越权。

已有经过验证的规则若使用 `scope.namespaces`，可以人工或由程序迁成对应 `scope_bindings`。同表出现多份不一致绑定时必须显式报冲突，不能擅自挑一份。自定义 scope 无绑定且不含 `public` 时仍可运行，但默认支持均被视图过滤，返回 `scope_filtered`；不能为了显示结果自动把 `[A]` 改成 `[public]`。

这部分已用 63 项回归检查支持过滤、范围切换、身份共享和权限变化。来源驱动、连接与表列授权的 291 项回归保持通过。客户数据库中的行权限与部署效果仍需单独验收。

## 仍需保留的保障

| 旧回归 | 应保留的行为 | 新流程的覆盖与缺口 |
|---|---|---|
| `test_publication_groups.py` 的独立成果、共享名称冲突、失败修订保留旧头 | 无关草稿可以继续发布；冲突不能覆盖旧结果 | YAML 工作区已有修订、独立发布和名称冲突测试；新增 `test_construction_publication_lifecycle.py` 检查合并后的全局环和旧头保留 |
| `test_pipeline.py` 的重复执行、不同列名、身份去重 | 相同类型与身份键生成稳定节点；多位置增加支持 | `test_graph_construction_executor.py` 覆盖改列名、多位置、跨源属性增补；真实 CSV/Excel 工具测试覆盖保存、验证和发布 |
| `test_resume_pipeline.py` 的失败重试保留成果、同名列不删除独立投影 | 工作区可恢复，当前候选失败不撤回此前发布版本 | runner、workspace 和真实 worker 的两次运行测试已有覆盖；尚未用真实模型证明只处理未完成工作 |
| `test_pipeline.py` 的失败关系、原子更新和删除 | 无效端点、冲突或中断不能发布半张图 | executor 验证端点；manifest 原子提交；新增写入失败后重开工作区测试。跨草稿协调身份变更、撤回草稿及依赖更新仍需设计 |
| `test_pipeline.py` 的预算失败和 discover-only | 超预算不能伪报完成；仅发现模式不能发布 | runner 共享截止时间、Harness 调用预算、工具硬性禁止发布已有测试 |
| `test_retention_lifecycle.py` 的排除值、异常正文与凭据 | 未授权值和异常里的秘密不能通过工具、输出或日志泄漏 | 表列权限、证据只存摘要、worker 密钥测试已迁移；新增来源异常正文不回传、不落盘测试 |
| `test_retention_lifecycle.py` 的进程终止 | 关闭或杀死进程不损坏已发布成果 | worker 取消、清理和进程测试仍保留；YAML 写入失败回归与 manifest 提交前真实强杀测试已补，重开工作区仍可读取旧图并恢复草稿 |
| `test_pipeline.py` 的 scope 支持撤回与过滤 | 不同范围的名称、属性、关系和文档证据分别授权 | 新 scope_bindings 与逐条支持过滤已迁移，覆盖同节点私有属性、范围切换和来源权限变化；草稿撤回及跨依赖撤回仍需设计 |
| 来源、列或目标范围缩小后禁止旧数据继续展示 | 权限收窄立即生效 | `test_construction_graph_access.py` 覆盖整图拒绝、历史保留、模型预算变化不误判权限变化；范围切换按支持过滤；来源/列授权或绑定变更拒绝旧图，当前不按新来源权限自动重新裁剪旧图 |

当前来源上下文按整个输入集合计算。任意来源文件或文档变化，会使所有草稿的旧验证失效。随后发布的新图只合并当前上下文中已验证的草稿；其他旧成果保留在历史文件里，尚未重新验证的部分不进入新发布头。这与旧流程“只重做受影响依赖”的行为有差距。后续需要逐草稿的来源依赖指纹，再结合共享身份和关系依赖确定重验范围；当前不能跨上下文直接拼接旧图来伪装复用成功。

## 可退役的算法专属断言

这些断言绑定已移除的执行方式。本轮已按[退役清单](retired_workflow_tests.yaml)删除 111 个此类测试函数及 9 个无引用夹具文件；其背后的安全保障保留或转由新入口回归验证。

- `test_resume_pipeline.py` 中固定 `table_refs` 调用顺序、工作流版本变更后恰好重跑某张表、T2 重试次数、`reused_rules` 的固定值。新 Agent 自主选择工具，程序不再预排这些阶段。
- `test_pipeline.py` 中自动识别固定样例并生成 7 条规则、固定 `parent_of` / `uses_measure` 算子、`rules.yaml` 导出、自动将文档转成 `analyzes` 事实。新实体类型、关系和映射来自 Agent 的 YAML；知识文档先作为可读取证据，尚无独立的文档事实抽取输出契约。
- `test_publication_groups.py` 中 SQL 暂存分区数量、`publication_ids`、`iteration_work` 表布局和旧 `RuleSpec` 依赖分组的精确形状。新工作区使用不可变 YAML 版本和 manifest；全局约束及失败隔离仍必须验证。
- `test_retention_lifecycle.py` 中旧 `StructuredModelClient` 的 SSE 分片、opaque 列 ID、ProposalBatch 响应、HTTP 请求体和重试计数格式。传输和上下文由 Harness 管理，相应回归应在 Harness 适配层验证，不应恢复旧协议解析器。
- 自动执行历史固定规则、`demo` / `verify` / 旧规则 rollback 等入口测试。历史图的只读权限、查询和导出测试仍应保留。

## 留存要求已发生变化

用户明确要求保留完整运行轨迹并由用户主动清理。新 Harness 会保留授权工具结果和模型交互，因此“所有源行、模型回复及工具消息在所有产物中均不存在”已经不符合当前要求。旧 `record_trace=False` 的严格零轨迹运行也不适用于需要持久会话的 Harness。

仍需保证：凭据不进入配置文件或导出轨迹；未授权列不进入工具结果；后端异常正文不回传；证据摘要不伪装成完整原始数据；清理只由显式操作触发。测试应把授权的诊断留存与未授权数据泄漏分开。外部模型供应商、操作系统日志和备份的留存不由这些应用测试证明。

## 本轮审计发现并修复的实际问题

1. 两份各自无环的草稿，合并后可能形成环。发布前现在检查合并图的 `acyclic` 约束；冲突草稿保留，原发布头不变，独立草稿仍可发布。
2. 来源适配器抛出的普通异常原先可能穿透 MCP，返回 SQL 或源值。执行器现在记录不含异常正文的失败码，工具最外层也阻止异常正文外泄。
3. 新图读取原先直接相信发布头的旧权限指纹。现在对比当前配置、发布头和图文件的权限指纹；不一致时拒绝读取。
4. 自定义 `scopes` 原先没有等价的逐条支持过滤。现已增加程序配置的 `scope_bindings` 及逐条支持过滤，恢复旧范围配置；授权不由 Agent 决定。

这些结果证明的是程序行为和模拟运行的边界。固定脚本、真实 CSV/Excel 执行以及 Harness 回环模型测试，都不能替代真实模型的自动发现质量、客户数据语义和数据库部署验收。
