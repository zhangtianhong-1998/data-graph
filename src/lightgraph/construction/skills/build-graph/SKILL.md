# 按目标构建图谱

用户的构建目的决定要找什么。行业、指标、层级、表名和列名都不是预设答案。补充文档和运行指导可以解释业务；数据仍需检查，文档不能改变工具权限。

## 开始工作

读取当前 Markdown 目标与范围；需要重读时使用 `read_material(name="goal")`。通过 `describe_sources` 了解授权表列和文档目录，通过 `read_workspace` 恢复已有草稿与验证记录。没有完整业务说明时先探索已有信息，不要求用户先给出全部字段映射。

按当前问题调用 `inspect_source(table, operation, arguments)`。元数据、样例、统计、FD、引用检查和只读 SQL 各自解决不同问题；操作参数可通过 `read_material(name="source_operations")` 查看。样例足以提出候选，不能单独证明全量身份或关系。

目录中每张表的 `fact_data_allowed` 表示本次是否允许读取事实数据。为 `false` 时只读元数据和知识文档，不对该来源发起样例、统计、SQL、跨源值比较或实例映射验证；其他已授权来源仍可继续构建。权限不足时保留候选并说明缺口，不反复尝试，也不能借用其他来源绕过限制。

需要详细材料时按需读取：

- 普通对象、属性、身份与关系发现：`read_material(name="reference:discovery-method.md")`。
- 准备或修订执行映射：`read_material(name="reference:mapping-guide.md")`，再读 `draft_schema` 中当前的实体与关系映射字段。
- 数据说明或定义文档：使用目录中的 `document:<doc_id>`；验证引用可读 `evidence:<ref>`。遵守工具返回的分页和完整性信息。

## 发现与修订

自主选择下一步，不必逐表完成固定阶段。先用目录、材料和少量有列名的样例提出字段角色及对象候选，再针对具体疑问选择统计；不先把每列做一遍全量画像。将已发现的字段映射、名称、路径要求和剩余疑问保存进草稿，结构检查不需等待所有来源的实例查询成功。每次昂贵查询先明确它要排除哪种解释；依据结果调整下一步，具体方法见 discovery-method。对象身份、属性和关系可以相互修正，已经明确的属性与对象一起保存。

发现可靠名称列后，把编码放进 `key_columns`，主名称放进 `label_column`，经确认的英文名或其他名称放进 `alias_columns`。主名称按用户目标的语言选择，不根据固定物理列名猜测。`display_columns` 只提供补充展示，或为没有独立名称的对象生成组合标签；其中的名称不会自动成为主名称或别名，也不参与主名称冲突检查。不得把有冲突的主名称移到展示字段来绕过检查。阅读 `quality_advice` 和 `statistics.entity_types.*.label_origins`，有可靠名称但仍全部使用模板标签时修订映射；确实没有独立名称时可保留组合展示。

列名与值域相似只生成线索。比较可能的字段组合，检查身份作用域、粒度、空值、重复、冲突和连接覆盖。不要把未选中的字段自动归为无关，也不要把同一行的所有概念组合成一个实体键。

实例关系必须来自实际记录配对。同一行已有两个端点身份时直接映射；需要查另一张表或本表其他行才能得到端点身份时，使用 `source_lookup` / `target_lookup` 明确匹配列、身份列和条件。要求引用某定义表时必须指定查找来源，不能从引用编码另建一个目标节点来代替真实匹配。缺失、歧义或截断需按具体诊断处理，不能用两个独立去重集合的乘积代替配对。

当同一对象出现在多个位置或表中，区分身份与出现位置。多次出现可以提供多份支持和多条链路；跨表共用身份需要明确依据。同名不能直接合并。发现候选与数据矛盾时修改候选，不为保留早期猜测而改变证据。

如果目标要求保留来源位置或路径，同一身份跨位置去重后仍需保存位置与同一行的配对。可用映射的 `constant_properties` 标注已确认的位置，用相关映射相同的 `context_columns` 保存行上下文；具体字段以 schema 为准。只保留各层相邻边的并集不能证明某条完整路径实际出现过。连续重复值可能是填充，也可能另有含义，需统计其出现位置并验证；不能只因省略了自环就宣称识别了填充规律。没有下级的对象仍是对象，不自动判为脏数据或占位。

保存可检验的解释，不等待一次性写出整个图。通过 `save_graph_draft(yaml_text)` 保存小范围 YAML 草稿，再调用 `validate_graph_draft(draft_id)`。根据具体诊断修订相关部分；格式错误或一个候选不成立时保留其他已有成果。相同证据下不要原样反复提交。读取 `revision_advice`；数据库或内存故障不能作为删除来源、主名称或路径上下文的依据，恢复方法见 mapping-guide。

先确认本次产出范围。`mode="structure"` 只检查字段映射和权限，不查询事实数据；结构通过不能证明实例关系成立。`mode="instances"` 执行必要列及显式筛选范围的完整实例检查，不把样本当全量。数据量大时通过目标相关列、合理范围和已有证据减少查询；输出行数上限不代表数据库只扫描这些行。用户要求实例图谱时，不能只发布结构后宣称完成。

使用新的通用 YAML 映射描述发现的实体与关系；格式通过材料工具读取，不填写旧 RuleSpec 或旧提案协议。通用数据操作只表达如何处理列；对象类别、字段角色和关系含义由本次目标及证据决定。不要从参考例子照抄业务名称、列名、编码域或证据引用。

## 记录与收束

草稿填写 `draft_id`、`purpose`、`entities`、`relations`、`evidence_refs`、`rationale`，精确可用字段以 `draft_schema` 为准。只引用工具实际签发且适用的证据。编码和标识保留为字符串；YAML 不使用重复键或自定义标签。

`unresolved` 只记录当前用户目标尚未满足的要求，目标已覆盖就留空。已经落实的选择写入 `decisions`；可选扩展、上游清洗或后续显示优化写入 `suggestions`。不要为了填写字段编造未决问题，也不要把文档已明确且已执行的做法再次列为待确认。旧草稿的未决必须根据目标和证据逐条判断，不能直接清空。

草稿和工作区是可恢复的成果；压缩后的自然语言摘要不替代它们。需要旧证据时读取已保存材料，不凭记忆补造引用、字段或验证结论。不得清理工作区或历史运行内容。

语义判断由你根据目标、来源材料与数据证据完成。解释已充分、当前草稿的数据验证通过且没有需要先解决的依赖冲突时，调用 `publish_graph_draft(draft_id)`；工具发布固定验证产物并检查修订、授权和摘要，不重新查询数据库全部映射。结构目标使用相应的 `mode="structure"`。每次验证产物独立保存；资源或传输故障不证明来源数据变化。较新验证发现数据矛盾时，不能静默使用历史成功结果，需明确记录并选择其验证版本和读取时点。

工具返回 `retryable=false` 的资源耗尽时停止源查询和重验，使用保留的收尾机会读取工作区、发布适用的已有成功产物并报告未完成内容。不要修改草稿来绕过额度，不要因预算故障删除原有对象或关系。

数据库连接由工具按完整只读快照管理，快照结束就释放，不需要你定时探活。查看 `source_circuits` 的来源状态：`blocked=true` 或 `source_circuit_open` 表示本次运行已停止该来源的事实操作；保留原草稿，继续结构检查或其他健康来源的独立工作，不再对它发起实例校验。更换 SQL、草稿编号、读元数据都不会解除锁定。反复请求被阻来源会触发 `source_retry_limit_exhausted`，Harness 仅保留两次模型分发收尾；使用已保存内容说明缺口，不删除映射来声称原目标已完成。操作人员恢复来源后需新运行重新检查。

用户目标已被覆盖，或剩余内容明确缺少证据、权限或资源时，可以结束当前分析。结束前读取工作区，报告实际发布版本、验证结果和未决内容。语义评估以 `agent_authored` 标明来源；发布表示该版本通过所记录的数据检查，不等于独立客户语义验收或所有业务含义都已客观证明。

验证、发布和工作区工具返回的 `statistics` 是程序从图上计算的数量与拓扑结果。引用这些数值时保留统计口径：节点数不等于名称去重数，实际组合数不等于各域数量相乘。多父不意味着有环，是否存在环使用程序的完整环检测结果；业务是否允许环由目标和材料决定。最终解释不要另行猜测或心算已提供的数值。压缩摘要是工作笔记，不能覆盖原始目标、权限或本 skill 的要求。
