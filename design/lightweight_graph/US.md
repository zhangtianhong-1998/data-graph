## 1. 范围与约束

### 1.1 输入

客户输入允许同时使用，且任一通道缺失都不能阻止其他通道工作：

1. **结构化数据**：Gauss/MySQL 数据库的完整授权元数据 + 按需读取的实例数据；或客户上传的 Excel/CSV。具体 Gauss 产品、版本、集中式/分布式、兼容模式和驱动尚未确定，按“能力预检 + 适配器”处理。
2. **知识文档**：Markdown 等文档。至少区分两类用途：解释表/列/编码含义的**数据说明文档**；描述分析方法、思路、指标的**分析知识文档**。同一文档可混合，按段落判定用途。
3. **可选补充**：BI 组件、历史 SQL、字段血缘。客户没有这些资料时系统仍须能完成结构发现与图谱构建（这是与 xiaomeng 现有输入契约最重要的差别）。

### 1.2 硬约束

- 源数据库只允许**只读**操作：只读事务、最小权限账号、单条受控查询；`INSERT/UPDATE/DELETE/MERGE/TRUNCATE/DDL/COPY/CALL/DO/EXECUTE/SELECT INTO/数据修改 CTE/锁语句`等一律拒绝。
- 数据库/Excel 返回的**原始数据不得落盘**：不保存结果集、样本、原始投影、含样本的 prompt、完整模型请求/响应、原始画像字典、逐行指纹表、DuckDB 源表副本、包含上述内容的日志与追踪。允许保存**抽取结果**：经白名单与发布校验的实体、关系、属性、别名、规则、数据说明、文档主张、来源绑定，以及不包含原始取值的计数与验证结论。结果类型不能成为保存源行、自由 JSON 或原始查询聚合返回体的通道。
- 图节点、边、规则、文档与支持账本写入客户指定的结果存储，凭证与源库只读凭证分离；本项目不提供源数据库写回能力。
- Excel 原文件属于客户输入资产，按上传资产策略管理；解析中间表只在内存使用；不执行宏、不重算公式、不自动访问外部引用，公式缓存值缺失时显式未决。
- 图谱为轻量属性图：不要求 OWL 推理、类继承体系、每个定义派生本体类型；允许节点带 `kind` 标签和业务实体属性。
- 首期不把每条交易/订单/财务观测值实例化；观测值是否入图必须由 ExtractionGoal 显式声明并单独给预算。

### 1.3 非目标

- 不做通用多 Agent 聊天平台、微服务、消息队列、图数据库集群。
- 不承诺“零数据库扫描的精确增量”（见 US-18/19 的边界）。
- 不承诺自动还原所有错误 schema 的业务含义（见 US-06）。
- 不把文档主张升级为数据库事实，不把名称相同升级为同一实体。

- **P1**：跨项目复用与可选 BI 补充。它们缺失不能阻止 P0 主流程，未执行的检查不得显示为通过。

### 3.1 三个独立的能力验收门

| 验收门 | 输入与允许的测试辅助 | 必须证明 | 不能据此声称 |
| --- | --- | --- | --- |
| E：执行链 | 人工固定 RuleSpec、合成数据、两类 Markdown；文档模型结果可用固定 mock 验证接线 | 销售费用列组、宽层级、文档上下文与主张发布、共享实体、属性级支持撤回、无落盘、幂等发布正确 | 模型能自动找出规则、正确理解分析文档或适应客户数据 |

## 5. P0 用户故事

### US-01：接收结构化数据与知识文档两条输入

**作为构图用户**，我希望提交数据库、Excel 或 CSV，并附带知识文档，使结构、实例与业务说明共同参与构图。

- **Given** 同一任务包含一个 Gauss 连接、一份 Excel、若干 Markdown，用途可为数据说明或分析知识。
- **When** 系统登记输入并检查访问能力。
- **Then** 每项输入有独立来源 ID、版本、用途、授权范围；表结构与实例读取接口分开；文档用途可修订。
- **Then** 没有 BI/SQL/血缘资料时结构发现流程照常工作，并在报告中注明“可选来源缺失”，不得以缺失为由失败。
- **Then** Excel 保留原始列名、工作表位置、前导零、空值与类型推断；解析产生的中间表只在内存，不产生持久副本。
- **Then** 文档解析按标题层级/表格/代码块切片，保留原始定位（文件、修订、标题路径、行号）；不执行文档中的脚本/宏/外部链接。

**验收**
- 只给 DB、只给 Excel、给 DB+Excel+2 份 Markdown、给零文档 四种组合都能进入同一流程，后三种不得崩溃。
- 任一文件缺失只在报告中标“来源缺失”，不阻断结构抽取。
- 上传的 Excel 原文件仍在客户上传区；工作目录没有新增 CSV/DuckDB/中间解析文件。

### US-02：确认 Gauss 实际能力并选择适配器

**作为部署人员**，我希望系统识别具体 Gauss 环境，避免把某个 PostgreSQL/openGauss 行为假定为所有 Gauss 产品都支持。

- **Given** 客户仅提供“Gauss 数据库”，产品、版本、兼容模式、集中式/分布式未确认。
- **When** 执行受控连接检查与能力探测。
- **Then** 报告产品、版本、驱动、只读事务、元数据读取、一致性读取、游标/分页、取消、超时、窗口函数、CTE、`FILTER`、JSON、`EXPLAIN`、可用的近似聚合、已有变更来源；未知项保留 unknown。
- **Then** 只编译能力矩阵确认支持的 SQL 形状；不支持时返回 `unsupported_dialect` 并说明缺口，不自动退回字符串拼接或放宽检查。
- **Then** 能力探测不创建表/视图/函数/复制槽，不修改任何源库对象。
- **Then** 无法建立只读保护时禁止进入实例探查，只允许元数据只读浏览。

**验收**：在客户实际产品/版本完成一次能力报告；模拟不支持能力时流程降级为“仅元数据 + 未覆盖报告”，不得静默兼容；驱动与版本写入运行契约。

### US-03：只执行受控的只读数据库操作

**作为数据管理员**，我希望发现智能体和规则执行器都不能修改源库或绕过访问范围。

- **Given** 使用只读最小权限账号，配置允许的库/schema/表/列/函数白名单。
- **When** 规则或智能体请求查询。
- **Then** 查询经过：结构化统计工具或只读 SQL 工具 → SQL AST 完整校验（恰好一条查询）→ 对象/列/函数白名单 → 参数绑定 → 只读事务 → 资源上限。每层均须通过；Agent 可以提交查询但不能绕过工具，事务控制只由适配器发起。容错的历史 SQL 解析器不能用作执行闸门（SDD §4.2）。
- **Then** 元数据明确区分工具表 ID、SQL 标识符和提案列 ID。已支持的 CTE 列名、UNION 输出别名、分组别名和标量子查询，在工具、目标过滤、Excel/数据库适配器各层保持一致；隐藏列遮蔽、大小写冲突和未绑定引用仍须拒绝。错误提示帮助模型重读授权元数据，不回显未知参数。
- **Then** 拒绝多语句、`INSERT/UPDATE/DELETE/MERGE/TRUNCATE`、数据修改 CTE、`SELECT INTO`、`COPY/OUTFILE`、`CALL/DO/EXECUTE`、DDL、锁子句、会话修改、递归 CTE（首期）、任意已知副作用函数、跨库/跨 schema 越权对象。
- **Then** 拒绝原因明确可定位；被拒查询不执行任何部分。
- **Then** 设置并确认 `statement_timeout`、`lock_timeout`、返回行/字节上限、并发上限、内存上限；超时/超限取消源库查询，报告 `query_timeout`/`result_truncated`，不能把截断结果当完整结果。
- **Then** 源库凭证与分析/发布存储凭证分离。

**验收**：F09 拒绝集全部在源库执行前被拒；合法 SELECT/聚合/CTE/受限 JOIN 可执行；参数注入、注释绕过、大小写/模式名混淆、同名函数重载均拒绝；任何拒绝都不产生部分结果。

### US-04：数据库与 Excel 返回内容不落盘

**作为数据管理员**，我希望数据库只按需返回数据，程序不保存返回内容。

- **Given** 样本中植入只用于测试的唯一 canary 标记。
- **When** 执行探查、LLM 判断、规则编译、批量抽取；成功、失败、取消、重试、崩溃、流式输出六类路径分别执行。
- **Then** 输出目录、临时目录、`sources.duckdb`、日志、追踪、异常附件、请求缓存、检查点、模型 SDK 日志中均不出现 canary 或完整 prompt/响应。
- **Then** 内存临时引擎按其实际版本验证关闭磁盘 spill，并设置内存上限；达到上限时减小批次或失败，不得自动写临时文件。某个配置值本身不作为无落盘证明。
- **Then** 只有通过输出契约的图事实/规则/数据说明/主张可进入持久化；`EphemeralBatch` 类型不提供序列化方法，持久化入口只接受独立结果类型。
- **Then** 日志只允许任务 ID、规则 ID、查询模板 ID、耗时、行数、字节数、错误类别；禁止 SQL 参数与响应正文。关闭 SDK prompt cache、APM body capture、core dump/交换（部署预检项）。
- **Then** 不建立原始投影逐行指纹表；增量状态只允许规则/图事实摘要与无源值的逻辑位置。keyset 最后一个原始业务值仅存于内存。崩溃或跨轮分析后，无法验证来源版本时重读整个受影响提交单元，不能只续跑未完成分区后拼接不同快照。日志不保存参数 hash、逐行 hash 或可还原取值的派生内容。

**验收**：F10 的 canary 放入本目标明确排除的源属性，防止与允许保存的最终图属性混淆。在成功、失败、取消、重试、崩溃与流式输出六类路径后执行 `lightgraph retain-check <path> [<path> ...] --marker <token>`，扫描明确提供的目录和已收集日志。测试还须单独捕获异常、模型网关与流式事件，检查原值及值派生标记；不能假定 CLI 自动访问部署日志或模型供应商记录。若无法满足（如操作系统 core dump 未禁用），报告 `retention_policy_violation` 并禁止接入真实样本。

### US-05：按构图目的选择分析范围与列

**作为构图用户**，我希望前端填写的目标决定抽取哪些业务对象、属性和关系。指标、度量、维度是一个可选应用场景，人员、组织或其他业务不应被强制归入这些类别。

- **Given** 一张宽表含组织、产品、指标编码、期间、金额、导入日志等列。
- **When** 任务目标选择“定义/成员及其关系”，不包含“观测值图谱”。
- **Then** 在发现前配置 ExtractionGoal：目的、关注与排除内容、探索指引、实体类型、关系类型、来源范围、禁查列和仅用于辅助验证的列。每轮新 Agent 显式接收同一冻结目标修订；全部目标字段参与依赖校验，变更只触发受影响范围重新发现。文档和预算通过独立运行配置提供，目标不能扩大权限。
- **Then** 对候选表做用途分流（定义/配置/事实/混合/未知）并给证据；不能仅因表名含 `fact` 就忽略其中定义，也不能仅因类型是数值就排除编码列。
- **Then** 为每张表产出“关键列候选 + 角色 + 排除列及原因 + 所需上下文列”，并解释哪些列用于身份、哪些用于关系、哪些仅用于过滤。
- **Then** 同一来源在不同目标下可用不同投影；不能把上一目标的投影缓存当作新目标结果。

**验收**：F03 中金额/期间/日志列不生成语义节点也不进入实体身份；`report_item_l2_sort_column` 被排除且保留来源展示；目标变更产生新计划版本。

### US-06：形成可修订的数据说明与 schema 冲突清单

**作为数据分析人员**，我希望在抽取前知道字段实际含义、异常和未确认事项。

- **Given** 完整元数据中存在空注释、列名回声、与实际值不符的描述、中文/编码/JSON 混存。
- **When** 系统读取元数据，并通过有界采样、画像和必要聚合探查列值。
- **Then** 数据说明区分 `declared`（声明）、`observed`（观察）、`inferred`（推断）、`conflict`（冲突），每项记录方法、覆盖范围（采样/分区/全量）、时间和文档引用。
- **Then** 名称/注释与实际值冲突时可定位（表列 + 冲突类型 + 计数 + 分层摘要），保留原声明，不直接修改源 schema、不静默纠正。
- **Then** 数据说明可保存聚合结论与已接受语义描述，不保存样本行；后续规则引用明确的数据说明版本。
- **Then** 完全无业务证据时保留 `unknown`，不得为填满类型而猜测。

**验收**：F13 覆盖五类冲突（注释与值不符、名为日期实为文本、编码前导零、同名列不同义、业务说明缺失）；每个冲突有可复现计数；错误 schema 不被静默当正确。

### US-07：识别实体列组、属性列与非语义列

**作为构图用户**，我希望同一对象的编码、中文名和英文名合成一个实体，排序值不建节点。

- **Given** `report_item_l2_code`、`report_item_l2_sort_column`、`report_item_l2_cn_name`、`report_item_l2_en_name`，实例 `(2150, 112, 销售费用, Selling expense)`。
- **When** 完成列组候选、函数依赖验证、角色判定与文档/语义核对。
- **Then** 形成一个实体列组：`identity_code=code`、`label=cn_name`、`alias=en_name`、`display_order=sort_column`；`sort` 不作为语义节点，只作为来源展示元数据保留。
- **Then** 验证 `namespace+code → label` 冲突；中文名可为空或冲突（报告），英文名可多值（别名）；不能把“一对一同期”当成无条件函数依赖。
- **Then** 实体类型与属性含义由目标、元数据、适用知识及数据探查综合判断；已有指标/维度模板不限制其他业务。仅凭 `report_item` 名称只能给候选类型，不能强制标成 Metric。
- **Then** 不属于任何列组的审计列、日志列、导入批次列应显式排除并说明原因。首批提案未解释的其他授权列进入有界补查；不能因已有一个有效对象组就宣称整表发现完成。剩余范围、弃权与预算延期分别记录。
- **Then** 只有一组 `l2_code/l2_name`（或任意单序号 lN 列组）时，判为**实体列组**，不得凭 `l2` 前缀生成父子层级。

**验收**：F01 中 `(2150,112,销售费用,Selling expense)` 只产生一个实体节点（含 code/label/alias 属性，sort 不成为节点）；列组角色可由规则复现；不相关列进入 exclusion 清单；同码多中文名产生冲突而非任取。只有单组 lN 列的变体必须判为列组、不产生父子边。

### US-08：按正确列组合做联合去重与截断保护

**作为构图用户**，我希望大量重复事实只产生有限的语义实体和关系。

- **Given** 同一指标/组织/产品在多个期间重复出现，事实行数远大于语义对象数。
- **When** 规则执行关键列投影和去重。
- **Then** 在数据库中计算联合 `DISTINCT`/`GROUP BY`，保留真实元组；禁止先对每列单独 DISTINCT 再笛卡尔相乘。
- **Then** 投影列包含实体身份与必要属性，或关系两端身份及其真实联合范围；名称/编码/英文名必须来自同一行/同一元组，不能来自三次独立去重。用于业务含义的分类体系、口径或版本不得因为“只选关键列”被丢弃。
- **Then** 投影结果超过 `cap` 时返回 `projection_truncated` 并按分区重跑，不得把部分结果当全量。
- **Then** 报告分别给出：源库扫描行数、不同元组数、返回/接收行数、最终图事实数；`DISTINCT` 可能扫描全表，不承诺成本与结果规模成正比。
- **Then** 观测值（金额/数量/日期）只在目标明确要求时投影，且单独预算。

**验收**：F03/F12 中重复事实扩大 10～100 倍时实体/边集合不变、图事实数不变；联合元组不产生源中不存在的配对；截断能上报并按分区恢复；DB 扫描量与返回量分开报告。

### US-09：从宽表路径构建实体和层级关系

**作为构图用户**，我希望把 L1～L5 层级列组转换成正确的成员和上下级关系。

- **Given** 每行是一条 L1～L5 路径（如 `3 经营活动付现利润 / 2 非付现调整项目 / 27 拨备 / 271 退款负债 / 2711 收入拨备1`）；末级不足时叶节点在后续层重复填充（如 `3/1/1/1/1`）。
- **When** 规则展开层级列组、验证实体身份，先按缺失位置切段，再在各段内压缩连续重复填充、产生相邻关系。
- **Then** `3/1/1/1/1` 压缩为实体 `3` 与实体 `1` 及一条 `3 →parent_of 1`；不得生成 4 个“贡献利润”或自环。
- **Then** `3/2/27/271/2711` 与 `3/2/27/271/2713` 生成兄弟关系 `271→2711`、`271→2713`；没有额外证据不得生成 `2711→2713`。
- **Then** `A→NULL→C` 默认不生成 `A→C`；空层不得先被删除再压缩。相同编码仅在身份已确认一致时压缩；跨层同码不同义不得错误合并。
- **Then** 空层、同码异名、跨分区同码、多父、环分别检查并报告；多父仅在分类体系允许 DAG 且证据成立时接受；不得按编码前缀自动补父节点，不得用缩进/展示顺序代替源数据事实。
- **Then** 编码体系与目标树不一致（如源 `2/24/26/261` 与目标 `28/2408/2608/2610`）时标记冲突，Agent 应结合适用知识、列关系和数据补查提出解释；无法排除歧义时保留候选，不能强制用户必须提供统一编码或完整映射。
- **Then** 重复填充、缺层、多父的处理策略写入 RuleSpec 并可审计；父子边带分类体系、作用范围、版本。

**验收**：F02 覆盖重复填充、缺层、两个同父 L5、编码系列冲突、环、多父 DAG；真实/样例表中“确定边”“未决边”“冲突边”分别计数；节点数与层级无关地稳定。

### US-10：发现列关系并落实为实体关系

**作为数据分析人员**，我希望知道哪些字段组合组成对象、物理列关系如何连接这些对象，以及最终哪些实体实例存在关系。

- **Given** A 表 a 列与 B 表 c 列都保存指标中文名，另有编码列、声明外键与部分重叠值。
- **When** 系统比较元数据、类型、唯一定位率、覆盖率、作用域、判别列、文档。
- **Then** 分别记录 `declared_fk`、`value_overlap`、`same_attribute_role`、`verified_reference`、`maps_to_concept`、`same_entity` 六类结论，并带验证状态、覆盖范围与证据。关系类型注册表见 SDD §11.1.1，各规范文档引用同一张表。
- **Then** “都保存指标中文名”可支持属性角色对齐，但不单独证明可 JOIN、同名记录同一实体或存在业务上下级关系。
- **Then** 跨表查询必须带关联条件；禁止无条件全连接；复合作用域整体比较，不能拆成单列阈值；多态引用按判别列分区。
- **Then** 通用列名、连续整数碰撞、部分覆盖不得升级为业务确认；未覆盖/歧义保留未决。`technical_link` 的技术核验状态和语义状态分别记录，值重叠通过仍可语义未决；`same_attribute_role` 等语义边独立产生。

- **Then** 每条关系保留有序列组、连接条件、声明/观察基数、对象字段组、端点身份解释及规则修订。按实际有效连接元组生成实体边，不能分别 DISTINCT 后拼出不存在的配对。
- **Then** 一对多、多对多可生成多条实例边；单个端点身份歧义才留候选，不能把所有关系限制成 n→1。
- **Then** 可选关系的完整空端点表示该元组没有关系，跳过并计数，不丢掉其他有效配对。复合键部分为空、非空未匹配和歧义分别报告，不按正常缺省跳过；`require_full_coverage` 同时约束探查与执行。
- **Then** 数据库声明与 Agent 推断分别保留来源支持；字段关系不能只停留在元数据图。只有技术引用依据时不自动命名为“使用度量”等特定业务含义。
- **Then** 宽层级规则的各层对象也进入关系端点目录。关系提案使用 `source_level`、`target_level` 指定层位；同一编码跨层出现时连接指定实例，缺失或错误层位不能猜测。

**验收**：F05 与 R03/R17 覆盖同名不同义、异名同角色、伪外键碰撞、复合键、条件引用、多对多与身份歧义；实体边可回溯到“物理列 → 字段组 → 关系映射 → 连接核验 → 实例支持”。补充宽表层级末级对象到责任中心的关系、同编码不同层位及未知层位拒绝；16 列离线场景见 `test_wide_table_recovery.py`，实际模型能力仍由 D 验收。

### US-11：用有预算的发现工作流确认结构规则

**作为构图用户**，我希望系统在必要时继续查证关键结构，而不是一次采样后直接生成规则。

- **Given** 初步画像提出“L1～L5 是层级列组”“某列是多态引用”“code→name 是标识关系”等假设。
- **When** 发现工作流选择后续探查。
- **Then** 每个假设记录“假设—待验证问题—探查—反例—规则状态”；智能体通过注册工具请求统计或只读 SQL，根据临时结果决定下一步。SQL 必须在工具内通过完整检查；不开放任意代码执行或数据库直连。
- **Then** 预算分三池：探查（DB 成本）、LLM（调用与 token）、时间/内存；候选生成不能吃掉核验预算。启动新假设前预留其最低验证成本；各阶段预留比例可配置，不作为固定业务要求。
- **Then** 预算耗尽时未验证规则标为未确认，相关范围标为未覆盖；不得因“没找到反例”发布为已验证。
- **Then** 每轮 Agent 能看到剩余探索轮次和工具额度，运行时在既定轮数内预留不调用工具的提交轮。达到探索边界时提交有证据的提案或明确弃权，不因末尾继续请求工具就丢失整个探索结果；超额工具不得执行。
- **Then** 工作流记录只保存结论、计数、方法、规则状态，不保存数据库返回行、样本、完整推理上下文与请求体。
- **Then** 跨任务修订受统一预算和可配置轮数限制。同依赖版本下无新证据、规则变化或范围推进时转为 `UNRESOLVED`；预算不足为 `DEFERRED`，不能通过重复调用耗尽预算后宣称完成。新证据或用户裁决可重新激活对应工作。探索弃权、空结果与尚未确认关系不能永久缓存为完成；用户发起下一次运行时允许有界重试，同次运行不反复追问相同版本。语义否定仍不能通过反复询问改成肯定。
- **Then** 可修复的提案合同错误进入至多两轮定向修复；修复只携带安全错误码和已签发引用，保留独立有效提案、既有排除约束及原始数据反例。合同未修复不能缓存为该表发现完成。
- **Then** 单条规则的 FD 修复失败不跳过其他独立规则；覆盖分析中部分提案延期时，已完整通过的规则仍经执行校验后发布。结果不依赖提案排列顺序，剩余覆盖保持延期，排除、语义否定和拓扑约束不变。
- **Then** 引用协议检查与编译、语义复核使用同一份已签发引用集合；当前文档的版本和章节引用能够贯穿整个过程。入口引用错误也有有界修正机会，不能在编译修复之前直接丢弃整批提案。错误诊断记录提案序号、字段位置和错误类别，不保存未知引用原文，不自动删除证据以绕过检查。
- **Then** 已授权且只有唯一对应项的精确列名可规范为内部列 ID；不模糊匹配、不推测跨表重名。合法列引用上的属性绑定合同错误交由逐提案修复，不能阻断独立有效规则；排除约束仍对全部提案生效。
- **Then** 列组或实体键把同类层级中多个位置的键组合为身份时，须另行审查它代表的是业务对象还是整行路径，并核对目标中的排除项。FD 通过不能代替对象粒度确认；审查参考跨修复轮已观察的层级，包括尚未编译成功的假设，但这些假设不因此获得发布资格。后续新层级也须触发对已暂存复合实体的检查；否定或未决不得通过改名、补属性或删除层级上下文绕过。
- **Then** 独立语义复核引用编译器持有的完整主张，无需模型逐字段回显。协议错误最多纠正一次且仍消耗原预算；否定、未决或条件不满足不能以协议重试为由不断询问到通过，FD 通过不能免除层级语义确认。
- **Then** 输出 Schema 与运行时的任务类型、弃权互斥约束一致。格式错误的已有重试携带临时原响应和安全诊断，重新检查提示长度并计费，不原样盲重试、不执行纠正回合工具；原响应不持久化。纠正范围锁定在首个可解析候选的明确无效槽位：补缺失字段、补足过短列表、修正引用标识符类型或已知拼写别名；有效兄弟、排除项、原列表成员及其他业务内容不变，后续重试不能扩大范围。无法保真时拒绝或按原任务整批弃权，弃权另行计数，不计为修复成功。语义审查即使格式不合法，已有否定、反证或未决也不能通过格式纠正改成支持。
- **Then** 相对层级缺少身份域、分类体系或层位含义时，在付费语义复核前进入定向修订；Agent 须按证据明确解释或弃权，不能填入固定业务默认值。合法独立提案继续处理，修订后仍须独立语义复核。
- **Then** Agent 逐条提交内存草稿，按提案反馈固定合同错误；有效草稿和排除约束不因其他提案失败而丢失。末轮或源查询额度耗尽后仍可进行本地提交，源查询权限和原 API 轮数不增加；未结束的提交标记待处理，明确全局弃权则不自动发布本轮草稿。
- 新层级发现使用业务计划接口，内部身份域、层位和执行策略由程序一致生成；旧规则的精确修订继续保留原身份域和条件。已有业务类型定义原样复用，不能被默认描述覆盖。
- 语义复核的引用纠正只允许替换未签发引用、补充缺失文档分类；原结论、条件和已有证据立场由程序保留。流式协议字节与实际回复内容分别限额，异常或未完成回复不能执行工具。
- **Then** 层级业务计划只要求明确对象、身份范围、列映射、位置与多父含义；编译器派生内部身份域、路径策略和证据绑定。来源内跨位置复用不等于跨来源共享；跨来源共享必须显式声明且通过独立复核。
- **Then** 语义复核的输出只包含判断、证据立场和条件，程序绑定本次输入主张；模型不抄写主张或 UUID。协议修复不能删除已有条件、改变证据立场或把否定转为支持；传输重试不冒充新的语义投票。
- **Then** 默认向模型服务发送完整严格输出 Schema；不支持时明确失败，兼容模式 `json_object` 须显式选择，不静默降级。请求 Schema 纳入共同容量预检和预算估算；服务端返回成功仍须通过本地全部契约、引用、业务与发布验证。
- **Then** 对模型最终 JSON，仅恢复整段单一代码围栏、BOM、字符串外尾逗号和字符串内未转义控制字符；恢复完整保留原值，继续执行全部格式、引用和业务验证，并单独统计。不得猜补截断尾部、提取夹在正文中的 JSON、覆盖重复键或接收非有限数值；工具参数不走此恢复路径。
- **Then** 临时理由、说明与审查解释使用一致的 8192 字符上限，提示和验证契约同步；完整保留原文，不以截断消除反证或条件。整体响应与请求容量检查仍有效，说明文字不写入规则证据或结果库。
- **Then** 宽层级可显式声明身份策略；`source_scoped` 仅适用于来源绑定的旧层级模式，`verified_identity_domain` 须与相对层级及独立证据一致。`namespace_local` 不等于来源隔离。未知或冲突策略进入逐提案修复，原请求跨同批及后续修复保留，改名、遗漏或置空不能绕过；最终暂存层级须按完整冲突历史复核。

**验收**：F01/F02/F05 的发现过程在预算内完成；预算减半时能正确降级为部分验证并报告；无证据冲突时不会强行合并；同假设的重复探查在同次运行内可复用有界内存结果；跨运行只复用依赖与覆盖仍有效的已批准验证结论，不能持久缓存查询返回体。**探索可核对性**：目标范围对象和候选假设 100% 有处理状态；L3 已验证、DEFERRED、UNRESOLVED 分开报告，不允许静默丢失，延期不计为发现成功（详细指标见 SDD §15.1）。自动发现验收须满足 §3.1 的 D。

### US-12：把已验证假设编译成受控原子操作并批量执行

**作为开发人员**，我希望一次确认的结构规则能反复执行，而不再逐行请 LLM 解释。

- **Given** 已确认的实体列组、层级列组、跨表引用规则。
- **When** 编译抽取计划。
- **Then** 计划只包含受控算子：投影、过滤、联合去重、分组验证、宽转长、连续重复压缩、条件关联、实体发出、关系发出、一致性检查；每个算子声明输入列、输出结构、作用范围、空值/冲突策略、验证前提、所需能力。
- **Then** 解释器不执行任意 Python/模板/SQL 文本；SQL 由适配器编译，参数绑定；同输入语义/规则版本/配置产生稳定逻辑结果。
- **Then** 执行器流式读取、批内组装为图事实；失败批次可幂等重试；不能执行的规则报告具体能力缺口，不以“下载全表到本地”替代。
- **Then** 规则必须有版本、实验/发布状态、变更原因；规则依赖未变且新增取值符合已确认模式时，只走执行器；新判别值、身份冲突或前提失效触发定向复核。

**验收**：F02/F03 的规则可由测试直接构造 RuleSpec 执行（不依赖 LLM），输出与真值一致；非法算子/越权列/未验证规则被拒绝；同一 RuleSpec 重跑结果幂等。

### US-13：共用语义实体并保留来源引用与权限

**作为构图用户**，我希望不同来源确实表达同一业务对象时复用身份，同时保留来源、权限与不同角色。

- **Given** A、B 两个范围分别声明同一指标，名称、单位、公式、期间/口径一致，但本地编号不同。
- **When** 生成实体与来源支持关系。
- **Then** 仅在身份判断及共享范围成立时生成共享实体，保留两份带范围的引用与各自编号。跨范围共享不是默认规则；明确禁止共享的说明不能因含“共享”等关键词触发合并。
- **Then** 命名空间、编号解析仍受来源约束；复合来源范围以联合记录保存，不得把两个租户和两个业务分别求并集产生不存在的组合。
- **Then** 同名、同码或摘要一致不能独立证明同一实体；不同编号也不自动否定同一实体。Agent 综合现有列关系、知识、数据和图上下文判断；冲突保留不同实体或候选。
- **Then** 属性级权限：A 提供的别名 X、B 提供 Y，B 不因共享实体看到 X；A 撤回后不影响 Y。实体拆分、别名修订、规则迁移留版本记录。
- **Then** 实体使用稳定内部 ID，业务同一性由可审计身份决策决定。事实去重可以使用规范内容索引，不能把 hash 相等当作语义依据。来源、权限和规则修订进入支持；同一事实可以有多份可独立撤回支持。跨客户隔离域不得自动共享。
- **Then** 重复对象只跳过重复建节点，仍处理新属性、位置、关系及支持。隐藏范围的身份裁决不能改变另一范围可见的实体数量、ID 对应或邻域。

**验收**：F04 覆盖同义不同编号、同名不同公式、缺定义、A/B 权限隔离、撤回；共享实体只一份、引用计数正确、越权属性不可见；不同规则对同一事实的支持能分别撤回；修改显示名称不无故改变实体 ID。**首次发布共享实体时即做最小撤回测试**：A/B 共享节点，撤回 A 的独有别名后 B 仍保留该节点与其他别名；不允许只做 union/upsert 不做支持账本。

### US-14：从元数据图看清表→列→跨表字段关系

**作为数据分析人员**，我希望从元数据图直接看清 A.a 与 B.c 的关联和证据状态，而不是只看到表与表的模糊连线。

- **Given** 两张表、各自字段、已确认引用、已识别的属性角色对齐和未确认候选。
- **When** 打开元数据图并展开表。
- **Then** 授权范围内始终可见 `Database→Schema→Table→Column` 包含关系（`has_schema`/`has_table`/`table_has_column`）；跨表边连接**具体列**，不是折叠的表节点；点击表可展开列；点击列显示其所属列组、角色、关联规则和证据。
- **Then** 提供"选择两张表 → 字段并排对照"视图：A.a ↔ B.c 的角色、类型、基数、覆盖率、关联类型、状态、验证时间。
- **Then** 图例/详情区分技术关联、语义对齐、业务关系与声明外键，以及候选/已验证/冲突状态；折叠只改变展示，不隐藏授权范围内的边统计。共享实体的 label、搜索、计数、属性与导出均按可见支持过滤。
- **Then** 可由业务实体回溯到贡献它的表列与规则；同名字段不会因显示名称相同被前端合并。

**验收**：F14 中 A.a 与 B.c 的“同为指标中文名”以列级边可见且带证据；仅折叠表时不丢失列级信息；候选与确认边视觉可区分；无列级关系的表不会显示伪关系。

### US-15：使用数据说明文档辅助结构发现

**作为数据维护人员**，我希望 Markdown 中关于表、字段和编码的解释进入对应探查的上下文。

- **Given** 一份说明组织层级编码的 Markdown，以及一份与当前表无关的业务文档。
- **When** 系统为某列组判断或规则复核选择上下文。
- **Then** 按来源、适用表列、主题、版本选择相关章节，保留文档位置；未关联文档不默认全部塞入上下文。
- **Then** 说明文档与数据库观察冲突时保留两者及冲突状态；自动生成的数据说明不得反灌成独立第二份证据。
- **Then** 文档中的指令文本不能改变工具权限、放宽 SQL 限制、要求持久化样本或修改输出 schema；上下文包只在内存使用。
- **Then** 文档增量按修订/段落内容版本定位；未变段落不重新抽取；删除文档只撤回该文档支持的结论。

**验收**：F06 中正确说明文档提升列组/层级判断且有出处；错误/过时说明被报告而不是覆盖观察；无关文档不进入上下文；恶意指令不改变工具行为；文档更新只重算受影响段。

### US-16：把分析知识文档接入图谱

**作为分析人员**，我希望从 Markdown 提取分析方法、适用条件和依赖概念，并与已有指标/维度关联。

- **Given** 文档描述“收入下降时，按区域和产品分析变化”，图中已有收入指标、区域维度、产品维度。
- **When** 执行分析知识抽取与对齐。
- **Then** 根据项目语义定义生成分析方法、问题、概念或主张，带关注对象、适用条件、文档版本和章节定位；现有 AnalysisMethod 等是默认模板，不限制其他领域词汇。
- **Then** “文档建议按区域分析”保存为文档主张，不升级为源库存在公式/能力/事实的证明；保留 `asserted/possible/recommended/conditional` 模态。
- **Then** 对齐不确定时保留候选，不按同名强行合并；文档变更只更新该版本贡献的内容。
- **Then** 分析文档可以引用已确认实体，但不能创建“同名已确认指标”；文档概念与数据库实体在图中以不同状态区分。

**验收**：F06 中方法、维度、条件可溯源；模态不被抹平；错误绑定被拒/未决；文档版本变化只影响对应主张。

### US-17：分批执行规则并原子发布抽取结果

**作为运行人员**，我希望在有内存与查询预算下执行规则，并区分已完成范围与待处理范围。

- **Given** 规则需要读取大量事实中的有限语义组合。
- **When** 按规则和分区流式处理源库投影。
- **Then** 客户端只保留有界批次；完整返回集不落盘；只有符合输出 schema 的图事实/规则/主张进入待发布区。
- **Then** 发布记录包含规则版本、完整提交单元、完成状态、覆盖计数；图事实与支持变更原子提交；失败丢弃未发布变更并保留历史。分区引用不得含源键值或键哈希；临时随机 token、序号不能充当跨运行稳定身份。当前以完整规则 all 代际发布，查询分区只用于内存中的执行安排；generation CAS 核对旧 head 全集，拒绝旧 worker 覆盖新代。细粒度独立提交范围须另行证明，不能默认为当前能力。
- **Then** 一致性读取能力不足时，不声明获得某一时刻完整快照；完整提交/快照范围写入发布记录。只有完整且一致的规则代际才可做基于缺失的支持撤回；截断、超时、跨页不一致均不得触发删除。
- **Then** 结果可导出（见 US-24），发布目录不可变；历史版本只保留发布结果，不保留源快照。

**验收**：F07 中规则执行与发布可重入；中途失败后重跑不重复、不丢支持；发布清单可核对节点/边/属性/支持计数；旧发布在新发布完成前保持可用。

### US-18：规则与文档未变时不重复调用 LLM

**作为运行人员**，我希望常规重跑只执行已验证规则，避免为同一语义内容重复付费。

- **Given** 来源结构、已验证规则、数据说明、文档版本未变，数据库没有新增语义定义。
- **When** 再次执行任务。
- **Then** 规则化实体/关系不再逐行调用 LLM；已有图事实幂等更新，不重复创建对象或来源引用；模型调用数应为 0（文档与规则均未变，**且新增数据符合已确认模式、没有未完成发现任务**时）。
- **Then** 出现未知判别值、同码异义、新口径或违反已验证规则的形态时，只对受影响模式做定向复核；不能因为 schema 没变就跳过语义例外。
- **Then** 没有可靠增量信号时，允许重新执行关键列 `DISTINCT`/分区投影，在内存中与已发布图事实对照；报告明确“本次仍发生数据库扫描”。
- **Then** 不建立原始关键列组合的逐行缓存/指纹库；允许保存已接受图事实的摘要与规则/文档/结构契约指纹。
- **Then** 新增编码若符合已验证规则直接产生实例；新值形态、冲突定义或未知判别值触发**定向**复核，遵守统一修订预算与轮数上限，不把所有新行送模型。

**验收**：F07 中原样重跑 LLM 调用 0、图集合不变、支持引用不增加；符合已确认规则的新增成员不触发 LLM；新形态只触发定向复核；DB 扫描成本单独报告。

### US-19：正确处理新增、修改、删除与共享引用

**作为构图用户**，我希望源数据变动后图谱既能更新，也不会误删仍被其他来源引用的对象。

- **Given** 同一实体由两个来源分区支持，其中一份引用被删除、另一份仍有效。
- **When** 重算受影响分区并完成验证。
- **Then** 只撤回消失的支持关系；最后一个有效支持消失后才按策略撤回实体或标失效。
- **Then** 只有可靠删除事件或该分区完成一致、完整的规则执行，才能证明旧支持应撤回；采样、超时、预算耗尽、不完整分页不能作为删除证据。
- **Then** 只提供更新时间且无删除能力时，报告“新增/修改可检测、删除未保证”；不能标为完整增量。
- **Then** 关键列修改需撤回旧含义并增加新含义；断点重放不造成双倍支持计数；既有 CDC 的载荷与 keyset 业务值仅在内存中消费，持久状态只存不含业务值的日志位置、完成分区与支持关系。缺少可靠旧分区/删除事件时重算相关分区，不仅凭更新时间撤回；不主动建立复制槽或修改源库。
- **Then** 节点存在、属性值/别名、关系、文档主张分别撤回支持；共享节点继续存在时，失效的独有别名必须消失。

**验收**：F07/F08 覆盖新增、修改、删除、部分失败、重复执行；误删计数为 0；共享实体保留；支持计数与来源范围正确；删除不可证明时明确未决。

### US-20：处理结构漂移、中断与不完整执行

**作为运行人员**，我希望字段变化或探查失败不会静默污染已发布图谱。

- **Given** 已发布规则依赖某字段类型、层级列组和文档版本。
- **When** 发生字段删除/类型改变/判别值扩展/规则升级/进程中断/知识说明冲突。
- **Then** 只使受影响规则及下游结果失效或待复核，记录原因；不因无关代码变更自动重做全部源库探查。
- **Then** 缓存规则的数据验证失败也必须登记待复核，不受“schema 未变”或“已经发现”标记阻止。复核通过后按新规则重算完整提交范围；旧发布保留为历史，受影响支持标明当前待复核状态，不能继续无提示地充当当前有效结果。
- **Then** 检查点只含逻辑任务状态，不含源行/样本/完整上下文；恢复时重新读取必要数据并再次检查权限与规则前提。
- **Then** 结构漂移、权限变化、能力退化、预算中断分别给出错误码和恢复建议。

**验收**：F08 在取数/变换/发布/游标提交间注入失败；状态正确、不误删、重试幂等；schema 变化只失效相关规则；恢复不需要源数据缓存。

### US-21：用固定样例证明结构与增量正确

**作为验收人员**，我希望用小数据证明关键行为，而不是依赖大规模运行截图。

- **Given** F01–F15 固定样例（P0）及明确真值，包含正确、反例与不确定项；F16 为 P1 可选 BI 夹具。
- **When** 执行单元测试、适配器契约测试和小规模端到端回放。
- **Then** 逐项核对实体集合、边集合、属性、来源支持、冲突、未覆盖范围；节点数量/压缩率不能替代正确性。
- **Then** 编码集合覆盖率与实体身份正确率分开报告。关系、别名和跨位置复用还须在唯一且正确的实体上核对，不能把多个错误副本的属性或关系取并集后宣称正确。
- **Then** 结构化规则可完全离线测试；Gauss 实际执行必须在客户产品/版本通过契约测试，其他数据库测试通过不替代。
- **Then** 测试真值不把分类答案/提示写进待抽取样本。固定 mock/回放用于执行链与编排回归；自动发现另用实际模型的受控留出集评测，真值不进入模型上下文，并记录模型/提示/规则版本与成本。
- **Then** 每个用例记录预期未决项，允许“正确未决”通过，禁止强迫模型猜中人工标签。

**验收**：F01–F15 全部通过（F16 在启用 BI 适配时通过）；E、D、I 分别提交报告；失败、漏发现、正确未决被显式计数；首版完成标准见 §8。

### US-22：控制成本并解释未覆盖范围

**作为运行人员**，我希望看清数据库成本、模型成本和未完成原因，并能调整后续预算。

- **Given** 已配置查询时长、并发、返回量、内存、LLM 调用/token 预算。
- **Then** 运行人员可显式把 `model.max_calls` 或 `model.max_tokens` 设为 `null`，分别取消对应的 API 总额上限；默认预算和 `0` 的含义不变。取消上限后仍统计实际用量，不影响源查询权限、内存、超时以及 Agent 无进展和提交机制。
- **When** 任务接近或达到任一上限。
- **Then** 按优先级停止新探查、取消超时查询、报告已执行规则与未覆盖的表/列组/分区；不把预算限制显示成完整成功。
- **Then** 统计分列：元数据读取、画像聚合、精确验证、去重投影、规则执行、文档抽取的查询次数/耗时/扫描量/返回量；LLM 调用数/token、规则与批准结论复用数；内存峰值。
- **Then** 日志保留规则与查询模板 ID、状态、计数、耗时，不记录含源数据的 SQL 参数或响应正文。
- **Then** 报告给出“继续所需预算”的建议（按未覆盖项估算），支持下一轮续跑。
- **Then** 本次规则已发布业务支持、但请求的结果范围将其全部过滤时，报告明确区分“没有抽取结果”和“当前授权视图不可见”；只给固定原因，不披露被过滤的范围值、事实或数量，不自动扩大权限。

**验收**：F12 在预算减半/超时/取消下输出覆盖报告与延期队列；成本账与运行日志一致；不出现“成功=true”掩盖未覆盖。千万行级演练（重复放大 + 语义组合增加）放在扩大试点前，不作为首条纵切或首版功能验收的前置条件；演练报告扫描量/返回量/耗时/超时取消与图事实数。

### US-23：管理规则生命周期（版本/审计/回滚）

**作为知识工程师**，我希望规则可版本化、可审计、可回滚，避免一次错误规则长期污染图谱。

- **Given** 一条已验证规则产生过发布结果，之后发现语义错误或来源变化。
- **When** 修订/停用/回滚规则。
- **Then** 规则有稳定 ID 与版本链，记录创建者（llm/user/import）、验证记录、影响范围、依赖规则；旧版本保留但不再执行。
- **Then** 修订生成新版本并按依赖图只重算受影响范围。
- **Then** 回滚到旧规则版本时，先检查与当前 schema/文档/身份绑定兼容性，再对**当前来源**重算受影响分区并更新依赖结果；不恢复历史源数据，也不能把旧图结果标成当前事实。
- **Then** 历史发布可作为只读历史视图查看（带时间、规则版本、来源状态）；“历史查看”与“规则回退”是两种操作，都写审计。
- **Then** 每条图事实通过支持记录追溯规则版本；规则版本不进入事实 ID。撤回支持不删除仍被其他版本/来源支持的实体和属性。
- **Then** 规则变更不得静默改变图身份；身份变更需迁移记录与别名/引用处理。

**验收**：F07 中规则修订只重算依赖分区；回滚后用当前数据重验并重算，旧规则版本的历史发布单独可查；每条边可追溯到规则版本与验证记录；没有源快照时不承诺恢复历史单元格。

### US-24：导出与互操作图谱结果

**作为交付人员**，我希望图谱、规则、数据说明能以标准格式交付客户，不绑定某个内部工具。

- **Given** 已发布图谱。
- **When** 执行导出。
- **Then** 输出节点、边、属性、支持关系、规则、数据说明、文档主张、覆盖与冲突报告；至少提供 JSON/YAML（程序用）与 CSV（节点/边，便于导入图库）；可选导出 DataHub metadata-file 或 Neo4j CSV。
- **Then** 导出只含当前调用方有权限访问的已发布图结果，不含源行/样本/完整 prompt；按属性与支持裁剪，不能因实体共享泄露另一范围的别名。导出清单含版本、来源、生成时间、校验和。
- **Then** 导出可重复且稳定（排序确定、ID 稳定）；供增量对比与客户审计。
- **Then** 后续文档或身份复核失败时，收尾仍尝试导出当前授权的已发布图；不得导出 staging。报告分别记录业务图状态与导出状态，保留原始失败原因；导出成功不代表抽取完整。

**验收**：F15 中导出文件结构通过与 SDD 契约一致的 schema 校验；同一发布重复导出字节稳定（时间字段除外）；导入空图库后节点/边计数一致。

### US-25：配置敏感列与模型数据出域边界

**作为数据管理员**，我希望哪些列可以进模型上下文、哪些列只允许聚合统计，可以显式配置。

- **Given** 配置敏感列规则（列名模式、显式清单、数据分级）。
- **When** 构建探查上下文和 LLM 输入包。
- **Then** 敏感列默认只参与聚合/计数，不返回样本值；显式禁止列不进入任何 LLM 输入；无法判定时按敏感处理。
- **Then** 模型运行位置与请求保留策略可配置：客户环境内模型 / 已批准外部服务 / metadata_only。metadata_only 也只能向已经批准的执行位置发送授权元数据、无值统计与文档；没有任何已批准模型服务时不发送请求，只运行确定性路径。样本出域与供应商不保留策略必须另有明确授权。
- **Then** 配置变更写入运行契约；违反策略时拒绝调用并报 `data_boundary_violation`。
- **Then** 向量化只对已发布知识文本执行，不对源实例行执行；如客户认为向量可还原原文，需加密/访问控制或关闭。

**验收**：F10 中加入含 canary 的敏感列：模型请求中不出现其值；日志/追踪中不出现；关闭外部模型后流程降级为确定性路径并可继续。

## 6. 裁决与扩展用户故事

### US-26：候选展示、人工提示与可撤销裁决（P0）

**作为业务专家**，我希望在发现卡住时给系统一个提示或裁决，而不必重跑全流程。

- **Given** 系统输出未决项（编码映射、同名异义、层级方向）。
- **When** 用户录入提示/裁决并附来源。
- **Then** 提示作为 `created_by=user` 的假设进入发现流程，仍需数据验证；裁决作为有来源的映射，可消解冲突。
- **Then** 候选节点、边、身份归并和冲突可查看状态、原因、支持与反证。用户能确认、拒绝或撤销，操作记录作用范围、依据和版本，提交前显示受影响结果并做版本检查。
- **Then** 人工输入可追溯、可撤回，不覆盖自动证据；不强制所有任务人工确认。撤销后重新计算受影响投影，不直接删除原节点、来源和历史。
- **Then** 没有人工输入时系统仍须自动执行 P0 流程；证据不足的含义保持未决，不承诺自动消解所有业务歧义。

**验收**：F02/F06 中用户提供映射后冲突消解、图结果更新、溯源到用户输入；撤回后恢复未决。

### US-27：多源多任务隔离与跨任务复用

**作为运行人员**，我希望多个数据库/Excel/文档任务互不污染，同时共享已确认的全局实体。

- **Given** 两个来源任务先后运行，共享同一实体定义。
- **When** 第二个任务发布。
- **Then** 实体复用已有语义 ID 并增加来源支持；不复制节点、不串用来源权限；任务级预算/状态/规则隔离。
- **Then** 跨任务复用只复用“规则/实体/文档主张”，不复用源数据缓存；来源结构变化触发相关规则复核。
- **Then** 可以按任务/来源/实体查询支持关系与覆盖。

**验收**：F04/F07 中两任务共享实体计数正确；A 任务失败不影响 B；权限隔离成立；跨任务报告可查。

### US-28：接入可选 BI 组件/SQL/血缘

**作为已有 BI 资产的客户**，我希望系统能利用已有 BI 组件、SQL 与字段血缘，提升候选质量，但没有这些资产也能运行。

- **Given** 可选的报表组件、SQL 执行记录、字段血缘文件（格式可适配）。
- **When** 启用 BI 适配器。
- **Then** 提取表/列/组件/血缘证据，作为元数据与关系候选的补充；血缘只作为证据，不单独确认字段等价或业务关系。
- **Then** 六类文件不再强制；缺任意文件不影响主流程；适配器失败降级为“无 BI 证据”并报告。
- **Then** BI 数据同样遵守不落盘/模型边界策略。

**验收**：F16 中启用/禁用 BI 证据的候选质量与覆盖报告可对比；缺文件不失败；注入的伪血缘不被当成事实。

## 6.1 目标驱动的迭代构图（P0）

### US-29：每轮 Agent 读取固定目标与结构化知识

**作为构图用户**，我希望每次重新启动的 Agent 都理解同一个目标，并知道前几轮已经确认什么、尚未解决什么。

- 前端目标、排除、关注与提示形成 `GoalRevision`；本次运行固定修订，更新目标只影响后续显式运行或被重新调度的相关任务。
- 用户可为目标指导声明 `global / task / iteration / semantic_review` 及适用阶段；新 Agent 按同一冻结配置重新获得相应指导。全局指导、每轮发现指导和独立复核指导分别选择，上传知识文档不自动成为系统指令，指导不能关闭权限或验证约束。
- 每轮输入包含目标修订、任务职责、当前问题、相关对象/关系定义、规则、已接受与候选结果摘要、反对依据和预算；不依赖上轮完整对话。
- Agent 可按权限检索相关图实体、列关系、邻域、来源支持与裁决，结果有界并注明截断；不能把全图无界塞入 prompt。
- 新提案提交时校验知识与依赖版本；失效提案不覆盖新结果。对话、原始反例与查询样本不写入知识状态。

**验收**：R01 跨多轮目标一致；相关知识可取回；任务重启不丢未决引用；目标变更后旧提案被拒绝或重新核验。

### US-30：按目标形成项目业务类别、属性和关系

**作为平台用户**，我希望相同引擎可以处理指标、人员、组织等不同业务，而不需要修改 Python 枚举。

- Agent 可提议项目级对象类别、属性和关系定义；定义有版本、含义、目标相关性、条件和状态。
- 关系定义记录端点角色、方向和必要语义限定；仅在有依据时声明基数、互斥、逆关系或无环约束。
- 类别和属性定义不授予数据权限。输出许可来自用户授权和项目政策，禁止列不能通过动态属性进入候选或 accepted 输出。
- 程序继续校验输出结构、标量类型、引用、权限、大小和留存；不开放任意代码或自由 JSON 行转存。

**验收**：R02 切换至非指标目标不改业务枚举；R16 将排除列包装成新属性时仍被拒绝。

### US-31：处理数据中的未知模式并重新调度

**作为构图用户**，我希望规则处理后续数据时能发现新模式，重新分析并继续构图。

- 程序遍历完整必要投影；符合现有模式的新值直接实例化。重复对象继续补充属性、角色、关系和支持。
- 只有当前知识无法解释的新位置/角色、身份冲突、未知关系条件或规则反例才进入 `review_pattern`；缓存规则也遵守此条件。
- 已验证投影中同一键在其他列或层位出现，可产生 `unexplained_role_occurrence` 候选反馈；只保存列/规则引用和计数。相同实体已经正常复用时不重报；相同取值本身不授权归并。
- 表内对象、剩余列覆盖和关系发现分别记录状态。实体修订或新增对象成功后重新检查 T2；关系弃权、空表或无确认对象不能随实体规则被标为发现完成。
- 新 Agent 获得相关知识与问题，提出修订后重读受影响完整提交单元；无法验证来源版本时废弃旧 staging，不拼接不同快照。
- 同依赖版本下重复模式合并为一个待办；无进展转 unresolved，预算不足为 deferred。原始源值及其 hash 不进入持久待办键。
- 目录、投影、规则覆盖和图语义状态分别报告。数据已处理但仍有候选，与数据根本未处理完是两种结果。
- 提案修复和数据反例修订分别保留原因。FD 反例修订中若又遇到属性合同错误，后续任务仍能看到原 FD 失败；后轮不能重新纳入前轮已经排除的列。
- 运行报告分别给出已接受与候选的业务节点/边数，以及 `entities_and_relations`、`entities_only`、`candidates_only`、`empty` 等产出状态。元数据存在不能代表已有业务图，发现规则数量也不能代替发布与实例化结果。

**验收**：R05 后续 B→C 触发必要修订，B 保留同一身份和多种关系；已解释模式不再次推理。R06/R13/R14 分别覆盖缓存 FD 反例、罕见模式、预算与跨快照恢复。补充“首次合同修复耗尽、下次正确提案恢复、之后零模型复用”，以及“只有元数据、业务图为空”的独立报告断言。

### US-32：复核全图身份候选并可撤销归并

**作为构图用户**，我希望图建立后能发现重复对象，也能撤销错误合并。

- 图级检查读取固定版本 `GenerationView`：未受影响的有效发布、本轮完整待提交范围与明确标注的候选。替换范围里的旧事实不重复混入，staging 不提前成为当前 accepted 图。
- 从字段组映射、属性、文本、邻域及历史未决生成有界候选；不能先构造全部节点对再截断。报告候选来源、未覆盖和延期，另用 Gold 衡量召回。
- 同一运行内复核依据未变时复用候选视图，避免每个延期候选都重读全图；本连接写入、外部裁决或图版本变化后重新读取，提交时仍校验完整集合及证据。
- Agent 提出 same/different/unresolved；没有统一编号也可判断，同名同码也不直接合并。
- 报告分别统计明确拒绝本次合并的 `identity_rejected` 与证据不足的 `identity_unresolved`。拒绝本次合并不等于已经证明成员两两不同，不能据此生成 `different` 裁决；依据未变时不重复询问，新增证据后允许重新复核。
- A≈B、B≈C 不自动传递为 A=B=C；复核完整拟合并集合的反证、属性与关系约束。自动调用也必须展开此前接受的全部组成员，不能只提交下一对节点；相同组在本轮只复核一次。大簇未检查完保持未决，并发或版本冲突不得缓存成永久语义否定。
- 裁决有版本、作用范围和依赖；保留原实体、来源绑定及历史。撤销时重算受影响投影，隐藏裁决不改变无权限范围的可见身份。

**验收**：R04/R08/R11/R15/R19 覆盖非同码归并、传递冲突、撤销、权限、有界候选和待发布图复核。

### US-33：复核多重关系并保留独立支持

- 引用关系默认禁止实体自环，规则执行与发布两层都检查实际解析后的端点。自定义关系显式声明 `allow_self_links: true` 时，仍须把该许可连同完整关系定义交独立语义复核；不能依据关系名称或关键词猜测许可。
- 自环反例使对应引用规则失败，其他独立有效规则继续发布；反例以固定代码和计数进入新一轮关系复核，弃权保持未完成。旧引用发布按其实际规则修订退役重验，未发布的新草稿不能掩盖旧违规；历史保留。
- 实验评分覆盖全部输出关系的自环清单，并对新关系使用明确记录的真值映射；固定 `parent_of` 的正确率不能代表未评分谓词的正确性。来源支持叠加、跨谓词重复表达和错误边分别报告。

**作为构图用户**，我希望同一对象拥有多种合法关系，同时知道每条关系由什么支持。

- 同端点、同含义、同条件的关系合并为一条事实并累加支持；不同含义、时间、条件或分类体系的合法关系分别保留。
- 逆关系或同义关系只有在关系定义确认后规范化；真正互斥时补查或保留冲突，不统一二选一、不对所有业务关系禁环。
- 数据库列关联与 Agent 推断都能提供支持；它们若来自同一证据，不因转换两次就计成独立证据。
- 撤回一种支持时重算有效性，其他独立有效支持仍可维持关系；关系与端点裁决按依赖一起更新。
- 关系规则的标识同时区分关系名称和层级端点；同一对物理列产生两种已确认业务关系时，两条规则均可发布，不因标识碰撞而丢失其中一种。

**验收**：R03/R09/R10/R17 覆盖实际连接实例化、合法多关系、双来源撤回和多对多。宽表场景中同一末级项目到同一责任中心的两种已确认关系应各自存在、各自带支持，重复运行不重复造边。

### US-34：检查语义主张的肯否、条件、范围和反证

**作为构图用户**，我希望系统不会把“不共享”“仅历史备份”等说明误当成业务关系或身份合并的依据。

- 主张记录对象、方向、肯否、范围、条件、支持与反对依据、判断方法、状态和未决原因；结构化字段非空不代表业务判断成立。
- 关键词只作线索。否定、条件未满足、假设、废止、无关端点和矛盾证据不能触发 accepted 关系或归并。
- Agent 可综合松散知识、元数据、少量数据和已有图进行推断；不要求用户先给出完整规则，也不以模型自报高分替代核验。
- 推导结果不能为自身提供独立支持；先假设归并再用合并后的相同邻域证明归并属于循环依据。上游支持撤回须复核依赖结论。

**验收**：R07/R18 的否定关系、否定共享和循环证明不被接受；有充分适用依据的正例仍可接受，证据不足保持候选。

### 7.2 真值与执行记录契约

每个场景可以使用文件夹具或确定性生成器。独立评估真值至少包含：预期实体与属性、边及限定条件、禁止边/禁止归并、预期身份等价类、支持与撤回结果、正确未决和未覆盖范围。真值 ID 仅由评估器使用，不提供给发现 Agent，也不以本地运行 UUID 作为业务正确性的判据。

E 用固定规则校验执行；D 仅给正常授权输入并由评估器持有真值；I 记录真实产品/版本/驱动/权限环境。模型替身只能标记调度和约束覆盖，不能登记成真实模型 D。

执行记录包含 `commit`、输入或生成器版本、`mode`（E/D/I）、实际命令、报告路径、执行时间、结果和未通过子项。`not_run`、`partial`、`passed`、`failed` 分开记录；结果缺失保持 `not_run`，不能从测试函数存在推断 `passed`。

导出校验沿用 `src/lightgraph/schemas/graph_export.schema.json` 与代码中的实际契约，检查事实/支持分离、边端点、属性权限、状态和引用完整性。扩展动态词汇及裁决时同步升级契约，不另做只检查字段存在的宽松 schema。

保留检查须同时扫描原值及可枚举的值派生标记，并覆盖成功、失败、取消、重试、崩溃、流式输出；已有明确排除列 canary 检查不能替代分区键哈希检查。SQL、驱动、模型、工作台传输和部署日志各自记录范围。

首版要求 F01～F15 每项均有可执行输入、独立预期、命令与结果报告；新增 R01～R19 对应的需求见 US-29～34，并列入相关 F 场景。缺失真实 D/I 或客户 Gold 时，明确报告该验收门未完成。

## 8. 首版（P0）完成标准

1. US-01～US-26、US-29～US-34 的 P0 条款全部有对应验证；F01–F15 全部用例有固定真值与结果报告；E 执行链、D 自动发现与 I 实际接入与增量分别验收，未完成 D 不得宣称“自动构图完成”。
2. 在选定的实际 Gauss/MySQL 产品/版本完成受控端到端验证，分别说明适配范围：连接、能力探测、只读事务、拒绝集、超时/取消、元数据读取、DISTINCT 投影、发布。
3. 数据不落盘检查覆盖成功、失败、取消、重试、崩溃、流式输出六类路径；F10 canary 零出现，并核查临时引擎、SDK、模型网关、APM、交换与崩溃转储的部署配置。
4. 固定验收集上的实体、属性、关系、身份归并、支持撤回及权限与真值一致；禁止边、禁止归并和误删为 0。真实模型评测另报告精确率、召回率、误归并、漏归并与正确未决，不能据合成集宣称普遍零错误。
5. 报告明确列出未支持的 Gauss 特性、来源增量能力缺失、语义未决范围；不得出现“整体成功”掩盖未覆盖。
6. 客户数据上的语义质量单独评价，不以工程测试或 D 合成集通过替代；未有业务 Gold 时只确认客户环境中的结构与工具正确性，报告业务语义未验收。
