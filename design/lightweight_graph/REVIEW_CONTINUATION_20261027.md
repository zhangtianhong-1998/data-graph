## 已核实并纳入修复的问题

| 问题 | 本轮处理 | 检查边界 |
| --- | --- | --- |
| T2 弃权后随实体完成标记永久跳过 | 关系发现有独立工作项与端点版本依赖；同次运行避免重复探查同一版本，用户下一次运行可重试未决或延期任务 | 不为得到肯定判断反复重问同一个语义复核；预算与模型模式仍生效 |

| 每表首批提案遗漏其他对象后停止 | 按尚未解释的授权列安排有界 T1 补查，并记录剩余范围 | 列已解释不等于业务对象或关系召回完整 |

| 探查 Agent 看见统计，语义复核器只收到空对象 | 按算子允许的结构传递嵌套计数与列引用 | 不放开任意嵌套值、样本或自由解释的持久化 |
| 三处相同对象只合并第一对 | 每次判断展开当前有效身份组，把全部原始成员与证据交给复核及提交守卫 | 同码、同名和已有两两相似都不自动证明整组相同 |
| 新列或新角色出现没有反馈事件 | 从已验证的运行内绑定索引检测重复键出现位置，生成 `unexplained_role_occurrence` 安全引用与计数 | 候选提示不自动归并；已确认复用同一实体的正常出现不重报；不额外查询或保存源键 |
| 前端目标没有运行位置配置 | 目标增加 `runtime_guidance`，区分全局、普通任务、每轮发现和语义复核，可进一步限定阶段 | 用户主动配置的指导与上传知识文档分开，均不能改变数据权限或关闭校验 |
| 长说明超过一次上下文限制就阻断整表 | 文档上下文按字节和章节窗口处理；同一主张必须完成全部适用窗口的复核 | 后续窗口有反证、未知条件或预算不足时，前面窗口的支持不能单独授权发布 |
| 节点已在 SQLite 发布，后续阶段失败却没有导出文件 | 收尾阶段尝试导出当前授权的已发布图，并分别报告业务产出与文件导出状态 | 不导出 staging，不把导出成功改写为发现成功；导出失败不覆盖原始错误 |
| 规则标识未区分不同结构解释，事实标识重复计算 | 规则逻辑键纳入解释所需的结构字段；一次 `stage_fact` 内复用已计算的事实 ID | 保留事实去重、依赖校验和历史兼容；不以摘要决定业务同一性 |

角色检测、剩余列补查和关系发现仍是有界任务。它们分别报告检查数量、遗漏或延期，不能把“已执行这些检查”写成“任意业务模式均已发现”。

## 保留的合理约束

**可选关系不等于忽略坏数据。** NULL 外键和根节点没有父项是正常情形，但复合键只填一部分、非空值没有对应实体、一个键对应多个不同实体，需要继续核验。`require_full_coverage` 参与结构验证与执行，不能只存在于模型协议中。

**指导与证据分开。** 用户此前澄清的 Markdown 实际指前端填写的抽取目标内容。因此本轮为目标提供明确的运行指导字段，不把任意上传文件中的 `inject_at: system` 或提示词直接提升为运行指令。`global` 表示每个相关的新 Agent 都得到同一冻结指导，不意味着只发送一次后假定所有新会话自动记住。上传 Markdown 的用途、表列范围和章节出处继续作为知识证据处理。

**结构检查不能替代语义判断。** FD、值重合和引用命中只证明结构性质。独立语义复核继续检查方向、端点、条件、反证与签发引用；长文分窗不能省略后文中的限定或否定。模型模式为 `metadata_only` 时仍不能读取源实例，关闭模型时也不会自动完成自然语言推理。

**来源绑定与业务身份分开。** 绑定包含来源、命名空间和身份列，能避免不同列域中的相同局部码被无条件合并。已确认的共享规则和可撤销身份裁决负责业务复用。当前定义摘要用于已批准政策下的精确查找，不是仅凭摘要相等确认两个对象；改成随机 ID 也不能自动补上语义判断。本轮不迁移旧绑定或重写历史事实 ID，旧库迁移需要单独设计和验证。

**按整体约束归并。** 已接受 A/B 后，A/C 或 B/C 的下一次自动复核必须审查 A/B/C 全组。任何成员的属性冲突、禁止归并裁决、层级自环或环都会阻止接受。并发版本变化属于可重试失败，不能缓存成永久语义否定。
