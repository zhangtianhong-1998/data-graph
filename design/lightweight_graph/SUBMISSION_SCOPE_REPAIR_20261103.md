日期：2026-11-03。依据是用户提供的真实运行事件摘要和当前源码；本机没有该次运行的完整 trace、配置或客户数据。下面的验证是离线回归，不能替代客户环境复跑。

## 已核实的问题

1. `object_model_supersession_mapping_loss` 并非命名空间被其他对象占用。旧代码要求候选替换前后的 namespace 集合完全相等。列名启发式漏识别“责任中心”时，模型补充该范围也会被拒绝，甚至得到 `same_identity_scope / required_references: []`。多个对象可以共同使用同一 namespace 列。
2. 简版层级工具没有说明 `identity_scope` 的区别。`source` 表示表内身份，仍保留 `namespace_columns`；`namespace/global` 表示跨源共享，才需要有证据支持的共享域。字段说明缺失会诱导模型为通过校验而填写一个共享域。
3. `complete()` 的调用上下文重复包含输入中的文档、样本和迭代上下文。语义复核也走这条路径，重复内容增加输入负担。
4. 接口超时已使用配置值与阶段剩余时间的较小值，但旧 trace 只记录配置值。HTTP 超时是 I/O 等待限制，不能直接当作整次流式请求的总耗时。

## 修改及边界

- 候选对象可以在保留既有映射的前提下追加 namespace；删除或替换原 namespace 仍拒绝，已验证或已发布对象仍须走规则修订。编码、名称、别名和位置映射的保留检查不变。
- 两种层级工具统一解释身份范围。共享域错误指向 `shared_identity_domain`，给出明确修订选择，不自动填域或改变身份范围。`claim` 类型错误反馈预期的 JSON 类型，不猜测字符串内容。
- 文档、样本和迭代反证在输入中保留一份完整内容，调用上下文使用引用；没有裁剪证据或放宽复核标准。
- trace 增加实际 HTTP 超时、阶段剩余时间、每次请求耗时和固定枚举的运输失败类型，分别记录重试。

对象、层级和概念草案在编译期间遇到复核请求中断，现在保留为 `semantic_review_interrupted` 候选，原始失败码单独记录。恢复后可以重新审查相同映射，无需为了请求超时而改变结构。复核通过只关联待发布规则，实际发布成功才关闭候选。独立关系发现分支的预算提前退出逻辑不在本次修改范围内。

中断记录不能覆盖同一材料下已有的非中断候选。已签发的必读证据与反证继续保留；涉及业务条件或恢复义务时，只保存安全指纹，恢复后须重建原约束。未得到结论与语义否定保持区分，历史反证不能因为发生超时而消失。
