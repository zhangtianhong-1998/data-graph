## 已实现的行为

| 范围 | 本轮变化 | 主要实现 |
| --- | --- | --- |
| 全局目标与跨任务迭代 | 保存目标修订和结构化工作项；每个新任务收到同一目标、相关规则与失败类型。中断任务可恢复，无进展保留未决 | `runtime/iteration.py`、`pipeline.py`、`context.py` |
| 平台业务定义 | Agent 可提出项目内对象、属性和关系定义。页面与命令行省略类型列表时均按目标发现；显式指定类型仍保留约束，指标词汇保留为模板。动态定义不能放宽列权限或覆盖内置字段语义 | `semantic_schema.py`、`store/policy.py`、`discovery/models.py` |
| 语义确认 | 删除从“引用、使用、共享”等关键词直接确认关系或身份的路径。独立复核主张端点、方向、肯否、条件和已提供证据；证据不足保留未决 | `discovery/semantics.py`、`discovery/workflow.py` |
| 物理关系实例化 | 保留字段组和物理列关联，基于实际连接元组生成对象边；支持一对多、多对多。重复对象仍积累属性、角色和来源支持 | `discovery/references.py`、`rules/engine.py` |
| 数据反例修订 | 缓存规则遇到 FD、层级、身份或引用反例进入定向复核。列组走 T5，跨表引用重新走 T2；修订后重读完整提交范围，保留同表其他规则的新数据 | `pipeline.py`、`discovery/workflow.py` |
| 完整代际发布 | `partition_by` 只控制内存中的查询批次；规则统一用 `all` 发布代际，成功后原子替换全部旧头。不同快照的暂存数据不拼接 | `rules/engine.py`、`store/sqlite.py` |
| 待发布图检查 | 通过 `GenerationView` 检查待发布完整图的端点和拓扑；提交时检查整个发布头集合，检查不会提前暴露暂存图 | `identity/reconciliation.py`、`store/sqlite.py` |
| 身份候选与裁决 | 按名称、编码、定义和已接受邻域有界召回。模型可综合原始图事实与文档复核不同编码对象；用户可确认相同、确认不同或撤销 | `identity/reconciliation.py`、`web/app.py`、`IdentityCandidates.vue` |
| 可撤销归并 | 原始事实及支持不改写，只在当前授权视图投影归并。保留不同关系与多份支持，阻止错误传递归并、属性冲突和层级环；新证据使旧裁决待复核 | `identity/reconciliation.py` |
| 工作台 | 默认展示 accepted 图，候选显式打开；提供状态和支持详情。配置与裁决有版本检查；高级 JSON 草稿在运行、上传和刷新前统一保存，冲突不丢稿 | `web/`、`src/workbench/src/` |
| 接入与资源 | 补齐数据库能力清单上传、校验、绑定入口；Excel 遵守项目内存预算 | `runtime/config.py`、`DatabaseSourceDialog.vue` |
| 导入导出 | 动态定义随图导出；导入的定义、事实、支持和发布头在同一事务提交，失败完整回滚。规则导出不复制旧分区值哈希 | `presentation/`、`store/sqlite.py` |

工作项保存引用、规则修订、错误类别和允许的统计计数，不保存源行或源值哈希。小样本仅在受限内存窗口供当前探查与独立语义复核使用，任务结束清理；不会作为跨任务记忆持久化。

模型路径不要求用户提供统一编号或结构化关联声明。关闭模型时，普通文字不会自动证明业务语义；确定性路径可以使用明确的 `lightgraph-semantic` 声明。这种声明供固定规则/合成测试使用，不能作为真实模型发现能力的证据。

## 已转为回归测试的关键反例

- 否定关系、否定跨范围共享、条件未满足、证据端点不符：不能 accepted。
- 缓存规则遇到新增冲突：启动新的 Agent 任务；规则修订后新旧数据都进入正确图；下一次相同输入不重复推理。
- 修订同表一个列组：不能丢失其他列组此次新增对象。
- 人员/机构及自定义任职关系：无需修改 Python 业务枚举；实际多对多元组生成三条边，重复行不增边，排除字段不进入图。
- A 与 B、B 与 C 的两次归并：不能绕过完整簇复核；明确不同约束和跨范围可见冲突仍有效。
- 归并后新增直接关系或更长路径：旧归并不能制造层级自环或长环。
- 私有裁决、私有别名或支持撤回：不得改变其他范围的身份；撤销恢复原图，历史视图不被追溯修改。
- 模型等待期间图或目标改变、用户已有裁决：迟到结果不能覆盖新事实或用户选择。
- 新旧分区顺序变化、运行失败、并发发布：没有新增源键哈希，完整代际对账和比较后交换仍有效。
- 导入中途失败：定义和支持不残留；随后重试另一合法定义可成功。

## 当前限制与后续验收

1. **反例识别有范围。** 当前调度器接收已注册的 FD、层级、引用、身份等执行错误。它不能发现所有尚未被执行检查表达的业务新模式。未决任务以依赖和安全统计计数抑制重复；若源数据变了但错误类型、计数和依赖都未变，尚无可靠源版本标记自动区分，需显式重新发现。
2. **图级复核有上限。** 默认检查至多 5,000 个业务节点、256 个候选对、8 次模型身份复核；报告保留省略计数。召回目前依赖名称/编码/定义和邻域索引，没有覆盖所有松散知识的潜在语义关联。不能把遍历过限额内节点解释为全图语义完备。
3. **发布与裁决分两步。** 待发布图先做结构、身份及拓扑预检并按完整代际发布；模型身份复核随后对未归并原始事实进行独立裁决，裁决有单独版本和并发检查。尚未将所有模型身份判断与业务事实发布合成一个事务。
4. **一般关系冲突尚未全部实现。** 不同合法关系可以共存；已实现身份与层级冲突检查。任意动态关系的互斥、时间条件、逆关系及通用基数裁决，以及归并前完整影响预览，仍需后续契约和用例。图复核阶段目前不会自行启动额外 SQL 探查。
5. **历史违规数据需单独迁移。** 新运行不再产生源值派生分区 ID；旧结果库可能仍含历史标记。本轮提供只读清点命令，没有静默删除历史发布、支持或用户文件。旧库治理需保留可恢复备份并重新构建相关结果。
6. **实际接入与交付仍有边界。** 真实模型 D、实际数据库 I、客户 Gold 的误发现/漏发现/正确未决评价尚未执行。当前 UI 按源码构建交付，wheel 未包含 Vue 构建产物。

旧分区标记清点命令只输出计数，不回显源键或 token：

```sh
.venv/bin/python -m lightgraph.runtime.partition_audit /path/to/graph.sqlite --fail-on-findings
```

哈希仍用于内容寻址、依赖版本和已获输出许可事实的稳定引用；它们不作为业务对象相同的证明。业务身份由规则解释、证据和可撤销裁决决定。
