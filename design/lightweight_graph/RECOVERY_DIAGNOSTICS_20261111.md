# 抽取期连接恢复与诊断修订（2026-11-11）

## 问题与证据边界

用户反馈的是抽取期间 Gauss 来源熔断：`database_reconnect_failed`、`stage=reconnect`、`category=unknown`、恢复次数为零，随后只能发布 Excel 指标树。维度与度量关联依赖的事实映射未完成。

这组摘要不足以确定远端关闭连接的原因，也不能证明具体是哪一个构造检查失败。本轮没有接入客户数据库或读取客户运行文件。已在实际适配器配合故障注入的测试中复现以下软件路径：

- 新会话的超时或取消能力检查失败，裸错误未进入有界恢复，出现与反馈相同的零次重试摘要。
- 运行时能力检查内部的只读检查误用 `snapshot_start` 阶段，虽然仍在新连接预检，却被当作后续事务资格拒绝。
- 探查语句的权限、预算错误被过宽的异常处理或游标关闭失败覆盖，失去原始分类。
- Gauss 目录中约束返回次序改变，会被完整对象比较误判为目录改变；实际键与引用可完全一致。
- 长运行的常规进程日志可以耗尽文件额度，使最终熔断原因无法留存。

## 连接生命周期与恢复

保留快照租约：需要取数时建立并校验物理连接，完整只读快照结束后释放；Agent 思考期不占用连接。同一快照内的查询不拆开重连，已返回部分数据的查询不自动重放。

新会话的只读、参数绑定、DISTINCT、超时、取消和运行时恢复检查统一记录准确阶段、检查项目和失败形态。失败会话先关闭，再在同一快照边界的三次恢复额度内换会话重新完成检查。额度、退避、取消和运行时限仍然生效。首次初始化的恢复范围不在本轮扩展之内。

未知驱动异常在新会话固定探查阶段可以有界恢复，但仍标记原因未知，不归因为网络或防火墙。未知应用错误只补充诊断，不自动获得重试资格。认证、权限、目录变化、能力清单绑定错误，以及已合格会话后来发生的只读资格拒绝，保持拒绝语义。

清理游标、取消查询或回滚时，保留先发生的权限、预算或取消错误，避免清理错误改变恢复决策。Gauss 约束集合按稳定顺序比较；联合键内部的列顺序、引用目标、键的增加和删除仍参与校验。

## 诊断与构建反馈

恢复与熔断事件增加 `cause_code`、`recovery_decision`，保留 SQLSTATE、检查阶段、次数和上限。代码值使用允许集合，原始驱动消息、连接串、SQL 和事实值不进入进程诊断。

128 KiB 进程日志中为终态数据库原因和进程退出分别保留空间。同一终态去重，最多保留四个不同终态；日志已满时仍可向独立轨迹发送这些有界事件。前端进程诊断显示原因码和恢复决定，避免下一轮只剩 `unknown / 0`。

列定义与事实关联继续区分：元数据仍满足授权与资格时，可独立发布度量、维度定义；若只读资格或目录已失效，工具明确返回 `metadata_catalog_requalification_required`，不再建议一个必然被拒绝的离线发布动作。可以另行验证并发布结构方案，但结构方案不代表事实成员和指标关联已经验证。

事实关联仍需源数据配对依据。不能因为度量节点成功发布，就补造它与所有指标的边。故障注入集成测试覆盖换会话恢复后，指标、两个维度成员、两个度量及四条关系完成验证和发布。

## 前端读取的独立修复

图谱首次读取与后续批次使用相同的有界重试：仅针对网络等待失败和 HTTP 502/503/504，最多三次，沿用相同请求和游标。权限及版本拒绝不重试。切换项目或候选范围时取消旧请求，并拒收迟到响应。

元数据刷新失败不再丢弃已经成功读取的业务图；首次读取失败会保留明确的重试入口。后端冷加载仍需解析已发布 YAML，这不是后端流式读取，也不修复抽取期间的 Gauss 连接故障。

## 验证与未验证范围

- 故障注入覆盖一次失败恢复、连续失败最多三次、取消和预算中止、权限不重试、无效会话不执行事实查询。
- 清理失败回归覆盖 Gauss/MySQL 只读探查和 MySQL 取消查询，原始错误分类不得被覆盖。
- 目录回归区分约束行重排与真实结构变化。
- 构建集成用例核对恢复后实际节点与关系，不只检查退出码。
- 前端回归覆盖首次请求恢复、手动重试、切项目、元数据失败和迟到响应；日志回归覆盖常规日志打满后的终态与退出记录。

本轮主回归：后端 3435 项通过，前端 377 项通过，前端生产构建通过。最后补充取消线程清理故障修复后，数据库、查询及关联发布相关 378 项再次通过（包含新增的两项用例）。未重跑独立启用的 310 秒 MCP 长连接测试，本轮未改动该传输路径。

以上是本地工程验证，不能代替客户 Gauss 环境验收。更新后须由加载新代码的服务启动新运行；若再次熔断，应先读取 `cause_code`、`stage`、`probe_code` 与 `recovery_decision`，再判断是否属于仍未覆盖的故障，不能仅凭 `sqlstate=unknown` 断言网络断开。
