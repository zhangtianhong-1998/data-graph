## 二、新抽取分支，验证 Agent 在定义草稿时做了哪些选择

1. 在另一份隔离工作区用冻结工作簿或其他已获准读取的宽表新建一次并行抽取，至少两分支、同一分支内至少两种可能重叠的投影。优先选已有独立答案的材料，涵盖同码同名、同码异名、互补属性和不同关系方向。记录真实授权、表列和样本版本。没有外键时照实记录。用已有冻结文件即可完成的部分优先执行；缺源权限时列出该项及已完成范围。
2. 逐分支取该次抽取自己的轨迹。记录 `inspect_branch_overlap` 的 tool call ID、成功回执的 `inspection_id`、涉及的草稿与修订号、Agent 看到的来源列及两侧角色。把保存时的 `branch_overlap_preview`、实际展开检查、实际修订定义、修订后验证/发布四件事分列。若 Agent 未调用，明确标“未调用”；缺历史轨迹标“未知”。比较草稿修订前后可证实的实体数、关系、端点和来源，不能归因的变化单列。
3. 让这些新分支进入自己的模型审查合并，复用第一项的核对口径。用“原始分支 → 分支验证后 → 确定性合并 → 模型审查合并”四列呈现。每列标注实测、缺证、未执行或不适用；分支无法复现修订前状态时不要推算节省量。关系分别列原始边、核实的事实及画布连线，单位写在表头。

最后用四句话回答：分支 Agent 实际做了哪些修订；相同输入下合并 Agent 净减多少节点；多少原始关系有证据可归入同一事实；“拨备”从几份到几份、还剩哪些冲突。发生错误或零增益也保留证据。报告完成后停掉本次隔离服务。
