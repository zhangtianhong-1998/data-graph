# 密钥绑定、跨源类型与初始化故障隔离

日期：2026-11-06。针对 `d96e911` 审查中复现的三个 P1 修复。实现结果和实际验证记录在项目根目录实施状态中更新；本文说明应保持的行为。

## 模型密钥跟随用户确认的配置

项目配置与密钥分两次提交时，后端不能把迟到的密钥绑定到其他页面刚保存的服务。写入和清除密钥都必须检查请求所依据的项目配置修订；写入还要检查预期的服务地址和模型，检查与变更在同一个项目锁内完成。

发生冲突时拒绝操作，保留已有密钥；前端保留尚未成功保存的输入，不自动重试到新地址。过期客户端缺少必要前提时也不能继续写入。测试使用假密钥与本地接口，不能用真实凭据测试错误地址。

## 跨源匹配保留值类型

数据库返回的 Decimal、日期和时间不能先变成普通字符串，再与文本编码匹配。探查阶段的引用检查与实例阶段的端点查找遵循相同的类型规则。文本前导零不丢失，不隐式把文本、整数、浮点、布尔或精确小数互转。

同类型精确小数允许不影响数值的精度表示差异；图中需要保留足以区分身份的类型信息。展示、YAML 保存和重新读取不能再次抹掉匹配类型。历史验证快照若采用旧类型语义，不能直接当作新规则下通过验证的成果；历史文件不自动删除或改写。

类型取自数据库驱动实际返回的值，不按列声明或字符串内容猜测。运行时保留 Decimal、date、datetime、time 的类型；落盘的显示值仍为普通字符串，身份、查找证据和行上下文另存类型。精确小数的匹配不经过浮点转换，也不受 Python Decimal 当前精度设置影响。`1.0` 与 `1.00` 在 decimal 类型内是同一身份；与文本、整数、浮点数保持不同身份。

新图记录 `source_key_semantics: driver_scalar_v2`，工作区上下文同步换版，旧验证需重新执行后发布；新旧语义的图不能直接合并。普通文本、整数、浮点和布尔身份 ID 保持原算法，数据库精确小数及日期时间身份 ID 会改变。已有发布图仍可按原权限查看，修复不会自动迁移其 ID、删除错误边或改写其内容；新运行必须重新验证和发布才能得到修复后的结果。

本轮未改变文件导入规则：CSV 的 `type_inference: text` 仍将非空字段当文本；Excel 沿用已有导入规则，包括日期单元格转 ISO 文本。数据库原生日期与这些文件文本不隐式匹配，不能据此宣称文件原生日期类型已被保留。SQLite 内存适配器拒绝直接装入带数据库运行时类型的文本，避免测试回放或其他内部调用无声丢弃该类型。

## 首次来源故障也按来源隔离

构图入口允许已正确配置的数据库在首次连接或运行能力预检失败后形成明确的失败来源状态。健康来源仍可读取、验证和发布独立成果。失败来源没有可信目录时，不伪造它的表列；依赖该来源的草稿不能通过完整验证或发布。报告必须保留失败原因与未完成范围，不能因为健康子图发布成功就报告全目标完成。

隔离不放宽凭据、表列授权、部署条件或查询预算。全局预算和配置错误仍按原约束处理；连接设置页面等需要完整连接成功的调用方保持严格行为。初始化失败状态只保存安全诊断，不记录连接串、密码或原始驱动异常正文。新运行重新尝试正常初始化。

## 验证要求

- 两个页面交错保存时拒绝过期密钥写入和删除；当前正确配置仍可保存密钥，刷新和重启后能正常使用。
- 数值与同形文本不匹配，实际数据库适配器的离线游标结果经过引用检查和构图执行仍保持类型；同类型正常匹配与 YAML 往返通过。
- 健康来源与初始化失败的数据库共存时，运行进入工具循环并保留独立成果；受失败来源影响的草稿受阻，报告保留缺口；严格调用方和全局约束不改变。

以上使用本地替身和合成数据验证程序行为，不代替真实模型自主发现、客户数据库接入或现场稳定性验收。
