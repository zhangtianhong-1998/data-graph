# 短连接、冲突隔离与运行配置

本次修改针对客户反馈的三类问题：数据库临时不可用后过早熔断、少数名称冲突阻断整份成果、配置默认值分散且页面过于复杂。客户数据库和原始轨迹不在当前环境；报告中的时间、次数和现场成因仍属于用户提供的观察，不能用本地测试代替现场结论。

## 连接与读取范围

旧实现已在最外层快照结束后释放物理连接，并非始终没有短连接。但是实例执行器把多个来源的快照同时持有到整份草稿验证结束，且新建替代连接时的失败可能直接进入终态。连接 generation 增长代表新建过物理会话，不能据此断言同一条连接持有了两小时。

新的执行顺序为：编译并核对授权 → 新建且检查只读能力 → 在同一快照内进行去重计数和完整投影 → 关闭快照并释放数据库连接 → 在内存中构建节点/边 → 下一次投影或端点查找。完全相同的完整投影可在本次验证中复用，其读取时段不会因复用而延长。CPU 处理、模型推理和其他来源查询不继续占用该连接。

每个实际读取组记录 `projection_fingerprint`、来源、开启与关闭时间、完成状态。验证记录使用 `independent_projection_snapshots`，不宣称整次验证处于单个时点。计数和对应投影仍须一致且完整；相同确定性 SQL 在不变数据上的行顺序差异不能成为拒绝依据。发布继续读取不可变验证产物，不因活库可能更新而全量重查。

正常新建连接不算故障恢复。连接建立、资格检查及 BEGIN 共享每个边界最多三次恢复额度；使用 1、2、4 秒退避，并检查取消、原有查询预算和运行截止时间。每次恢复都重新核对授权目录、驱动和能力。认证、权限或目录不匹配不按瞬时断线处理。已经读出部分行的失败查询不自动接续或重放。

恢复用尽后终止该来源本轮事实操作，保留安全诊断及实际恢复次数，不让 Agent 通过更换 SQL 或草稿编号再次启动恢复循环。`category=unknown` 仍是未知原因，不能改写成“防火墙掐断”或“数据变化”。依赖失败来源的关系会记录依赖未完成，不计入健康来源自身的连接失败。

## 冲突隔离的发布边界

完整读取结束且唯一诊断是 `same_identity_conflicting_label` 时，验证仍保持未通过，完整候选不变，但允许发布其中已经验证的无冲突部分：

1. 按实体身份隔离冲突节点，移除所有与其相连的边。
2. 保留其他节点、关系、名称、属性和来源支持；不自动改身份、不把冲突名称藏进别名，不按冲突编码清单删源行。
3. 发布返回实际数量与隔离数量，草稿保持需要修订。报告使用 `COMPLETED_WITH_GAPS`，表示已有可用成果，但目标仍有缺口。
4. 跨草稿共享身份出现名称矛盾时，对所有贡献版本共同隔离，不偏向先发布的名称。各原始发布快照保留。修订并重新验证后，从当前贡献版本重新计算隔离集合，可恢复已解决的节点。
5. 来源中断、投影截断、资源耗尽、身份定义或图拓扑错误不走名称冲突的部分发布通道。

同一编码在不同物理层位出现并不是冲突；相同身份和名称继续合并，多位置支持保留。冲突指同一类型、完整身份、访问范围内存在不相容的主名称。

`read_material(name="conflicts:<draft_id>")` 从保留的候选中返回身份值、冲突名称及映射来源，不需再次查询数据库。新修订尚未验证时可以读取旧修订的反例，但材料明确标注观察修订号，不授权发布新修订。跨草稿证据通过 `publication_conflicts` 读取。两者均按访问范围过滤并分页，隔离 ID 不直接放进前端可见图头。

## 配置默认值与保存

| 配置 | 新建项目及未显式设置时的默认值 |
|---|---:|
| 最大输入 tokens | 1048576 |
| 最大输出 tokens | 65536 |
| 模型调用总额度 | 2000 |
| 整次运行时限（秒） | 60000 |
| 模型接口超时（秒） | 800 |

Python 配置、生成 schema、Harness 直接入口和前端预设统一使用上述数值。已有项目明确保存的值保留；页面提供“使用默认额度”，填入后保存，下一次运行生效。运行中任务继续使用启动快照。

完整 JSON 编辑器默认折叠；常用配置直接填写。`working_context_tokens` 仍为原生压缩的工作阈值，默认 32768，与模型允许的最大输入分开；本次未把压缩阈值扩大到 1048576，也未修改 SDK 的原生记忆机制。

## 验证范围

本地回归包含：瞬时连接失败多次恢复、恢复额度共享、取消与预算不重置；投影间和跨来源连接不重叠、计数和投影共用快照、缓存不延长连接；冲突部分发布、反例跨修订恢复、跨草稿隔离与修复、权限过滤、不可变候选校验，以及前端配置保存刷新和隔离报告。

数据库驱动使用可控替身；Harness 集成使用本地脚本模型。真实网络/数据库稳定性、真实模型自主建模质量和客户语义仍需现场复验。本次没有启动客户实验，也不删除历史数据。

最终验证：后端全量 3197 项通过（启用原生 Harness 集成，无跳过），前端 343 项通过，TypeScript 与生产构建通过。测试确认工程行为，不代表真实数据库故障或客户抽取目标已经验收。
