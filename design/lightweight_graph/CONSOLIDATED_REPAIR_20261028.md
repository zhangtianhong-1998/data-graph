# 自动发现、概念建模与发布修改方案

2026-10-28。基线提交：`dd2e332a28d79d30db1b9f5a578f944948f9bee7`。先汇总三份分析，再按本文件实施；实施结果和未验证范围在末尾补充。原实验目录保持不变。

## 三份分析的共同结论与差异

第一份外部评审强调：原生模型协议被自写 HTTP/SSE 代替，模型直接填写复杂内部提案；身份键可把多个独立概念组合起来，导致无效提交与错误粒度同时出现。有效建议是采用原生 SDK、降低提案表达负担、把独立概念与上下文组合分开。

第二份外部评审补充了运行成本、关系发现反复修订、属性无法回填及大图展示问题。有效建议是字段级错误反馈、明确未决状态、预算分区、属性修订和可见的展示覆盖范围。不能把同一层级内部关系一律禁止，不能把所有未决草案直接发布成业务事实。

本项目诊断核对了来源与 Gold：水果组合名称由生成器和业务说明明确定义为报表项，并非全部由执行器拼接。3966/3966 证明报表项还原，不能证明指标、产品、渠道概念分解。额外复现了纠正后 invalid 状态仍残留、工具参数重复键处理不一致、有效规则三次撤销暂存后零发布的问题。

## 采纳和纠正

采纳：原生 SDK 协议适配；工具回合与最终结构化回答分离；保留服务端调用 ID；字段级且不回显源值的错误；历史错误与未解决工作分开；有限反馈和无进展终止；发现预算为执行/发布留余量；既有规则属性修订；受控概念分解与联合条件绑定；展示总量和范围；保留离线验收与真实模型验收边界。

纠正：

- AgentScope 的 ReActAgent/Toolkit 确实在运行，不能称完全未采用框架。
- response_format 与 tools 同时存在不能单凭源码断言导致了历史故障；分开请求是简化兼容契约。
- SDK 不保证所有非标准网关对象 arguments 都兼容，也不能代替业务校验、预算或留存约束。
- role 是枚举；entity_kind_hint/property_name 不是同一种固定枚举。业务中文名称与内部标识分开，不能自动翻译或随意注册来绕过审核。
- 不禁止合法复合键，不默认按连字符拆标签，不按同名全局合并指标。
- 三个概念与两条普通边不一定能保存产品和渠道的联合条件，须保留来源绑定/组合上下文。
- 同一层级有多个端点不意味着关系必然自环，也不应要求两条不同规则才允许发现关系。应做端点与已有关系预检，保留正常的无新增关系出口及失败上限。
- 现有候选图和工作账本并非完全不存在；缺的是发现失败的可操作反馈与适当持久状态，不能保存原始提示、样本或自由提案正文。
- 固定规则局部实验不等于整个 E 门已过；未宣称真实 D/I 已通过。30分钟/100万token可作后续实验目标，不能当作本次已经达成的指标。

## 本次实施范围

### A 原生协议

以 OpenAI SDK 承担 HTTP、SSE 事件解析和工具分片组装，保留项目的预算、字节/时间上限、完整响应验证和业务 Pydantic 校验。删除生产路径的手写 SSE 解析；禁止 SDK 内部未计账的重试。工具回合不附最终 response_format，保留原始 tool_call_id，拒绝重复键和截断参数。结构化审查的协议错误与真正语义未决分开报告。

### B 提案反馈

统一安全字段诊断：字段路径、约束类型、静态允许值，不回显任意输入值。草案错误累计作为遥测，不自动等于仍有未解决的草案；提供明确纠正/完成语义，已有有效草案继续验证。补充工具字段说明，维持内部严格 schema，不删除权限和事实值限制。

### C 运行收敛、发布与属性修订

发现使用独立截止时间，保留执行/发布余量；达到探索上限后以已取得合法规则完成正常全量验证和原子发布，后续发现记为延期。消除无进展反馈撤销无关暂存并反复重跑的路径；保持真正受影响依赖的一致重建。对关系失败按结构化原因有界处理，不删除自环保护。允许 coverage 对已有规则提出受约束的属性/别名增补，保持身份和关系语义不变，并重新完整验证。

### D 概念与上下文

新增受控概念映射能力：优先使用独立物理列；复合名称只有在明确声明分解规则、角色与定义依据后才解析，不默认猜测分隔符。独立概念身份与上下文组合分开，保留原始来源和联合绑定。为指标、产品、渠道建立固定小样例及反例；现有报表项图继续表示原始报表结构，不能通过重命名或合并伪装概念抽取。

### E 结果可读性

显式显示当前展示数量与完整数量/截断状态，展示可用的来源范围。错误报告提供可操作说明；保留详情检查。任意大图分页/虚拟化、导出格式重构、全库静态检查和自动付费 nightly 为后续独立工程，不在本次以无验证的大改引入。

## 验证

协议探针覆盖 SDK 实际路径、流/非流、分片、ID、截断、重复键、预算、错误脱敏；提案测试覆盖先错后改、错误定位、合法草案保留；调度测试覆盖关系失败/探索超时后核心规则正常发布及依赖一致性；属性测试覆盖英文名增补与身份不变；概念测试覆盖同指标多产品/渠道复用、联合条件不串配、不可声明时不拆分、同名不同口径不误并。最后运行 Python/前端全量测试和构建。

不调用现有大规模实验或自动付费模型；真实网关和客户业务验收在离线实现验证后另列结果，不能由测试通过代替。所有新增能力在文档中注明配置入口及边界。

### 第一批改动后的验收边界（后续进展见下节）

1. 没有重跑真实模型 D、真实数据库 I 或客户 Gold。旧 B22 的 7,200 秒、148 次调用、零业务发布是旧实现证据，不能用它评价当前改动，也不能用离线通过证明新的时间、成本、召回指标已经达标。
2. 保留严格内部提案 schema，补充字段说明和错误反馈；没有将全部工具重做成四个角色或把任意业务词自动翻译为内部标识。复杂层级和语义任务的模型可用性仍需真实评估。
3. 本轮把语义失败类别传回后续发现，没有添加“换个 JSON 再让审查投票”的循环。仅改名称、描述或删除条件不能推翻原拒绝；更细的缺失证据定位、原会话语义修订和发现候选裁决界面仍待设计。未决提案不会直接发布为事实。
4. 概念复用以已声明的角色、定义引用和命名空间为边界。相同含义但不同文档引用不会自动全局合并；源数据仅有复合名称、又缺定义声明时，仍应保留未决。三个概念之外的上下文节点用于保存联合条件，不能简单删成两条普通边。
5. 工作台翻页只覆盖服务器已返回节点。API 的 1,000 节点上限、全图构造成本、导出体积与离线 viewer 布局未重构；页面明确说明截断范围。这一批没有声称已解决十万节点性能。

项目的判断仍是：已有可信执行与发布基础，本轮补上多处发现失败恢复及概念建模能力；“真实模型稳定自动发现正确业务图”尚未验收通过。
