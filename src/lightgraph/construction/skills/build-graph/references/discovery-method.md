# 从事实数据发现对象和关系

本参考提供选择方法，不规定表顺序、固定次数或行业类别。始终先根据用户目的决定值得验证的内容，再使用当前工具获取证据。

## 对象与属性

结合字段注释、文档、类型、代表性值和重复模式提出对象候选。表可以描述一个对象、多个对象、对象关系或观测；不要默认“一表一个实体”或“一行一个节点”。

检查可能的身份列及范围列。编码重复可能只是同一对象出现多次，应检查它在相同作用域内是否对应一致定义。名称、英文名、别名与编码的对应要保持具体列对，不能将一个位置的编码错配到另一个位置的名称。

多个列只有组合后才唯一，不足以证明它们共同定义一个业务对象。先判断每个字段是否代表可独立复用的概念。关系或观测有自身粒度时可以保留相应对象，但其角色、参与者和含义需要单独说明。

已有候选只是待验证解释。新证据可以改字段角色、拆分对象、合并兼容属性或保留多个解释。修改已验证身份时记录范围变化和依赖，不能静默替换仍被其他关系引用的身份。

## 关系候选

从现有对象候选出发，检查声明外键、对应列、关联表、同一行的角色配对，以及不同位置的重复模式。按类型、粒度和目标相关性缩小范围，避免全表全列笛卡尔扫描。

查询应保留关系两端的联合元组。不能把两个独立 DISTINCT 集合相乘后当成实际关系。值域重叠、命名相似和函数依赖是不同证据，均不能单独决定业务关系名称。

验证端点身份、连接覆盖、空值、重复配对及基数。多对多可以是合法关系；检查它的业务含义和生成方式，不为获得一对一而丢数据。同一对象之间可以有不同角色或不同条件的多条关系，不能只按端点去掉差异。

需要查找其他记录才能确定端点时，用 `source_lookup` / `target_lookup` 绑定实际目标来源和匹配列。先明确组织、期间等匹配范围，再检查未命中与一对多；文本和数值不会隐式转换。目标节点已在图中存在，不等于该记录已在指定来源匹配成功。

来源中有方向信息时核对方向；没有方向依据时保留未决。跨表关系与跨表身份复用分开判断：两个对象有关联，并不意味着它们是同一个对象。

## 多位置与层级

只有数据或说明支持顺序及上下级含义时，才采用层级解释。编号、前缀、列序和名字中的分隔符可以提示候选，不自动证明层级。

判断位置是相对路径槽位、固定分类级别还是无序角色。同一对象跨位置出现不自动形成新身份。连续重复可能是填充，空位置可能是缺层；需依据当前材料选择处理方式，不默认越过缺口连接。

验证名称一致性、有效父子配对、自环、环和多父情况。多父可能意味着合法的 DAG，也可能是不同体系或范围混合；根据证据决定，不能通过放开校验掩盖错配。

字段换名后，仍可从注释、内容对应、结构和文档建立映射。所有上述方法也适用于不叫 L1/L2 或 CODE/NAME 的字段；信息不足时准确说明缺口。

## 证据与反例

区分元数据声明、样本观察、全量统计、完整投影和文档解释，记录各自版本及范围。检查结果不完整时不能宣称全表成立。

证据引用使用工具返回值。生成的解释和压缩摘要不能作为证明自身正确的独立证据。用户补充说明可以解释领域含义；物理字段是否存在、数据是否满足约束仍由工具检查。

发现冲突后提出能区分候选的具体问题，读取相关证据或统计。验证反馈用于修正字段映射、作用域或关系解释；无法区分时保存未决候选及缺少的信息。
