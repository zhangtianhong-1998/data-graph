# 数据抽取工作台交互原型

本目录是统一设计方案的可交互演示。使用本地静态文件和合成数据，不连接数据库、不上传文件、不调用模型，也不向后端发送请求。

从项目根目录启动：

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory src/lightgraph/workbench_prototype
```

浏览器打开 `http://127.0.0.1:4173/`。页面不加载 CDN、字体服务或其他远程资源。

## 可操作内容

- **项目目标**：编辑必填分析目的、关注内容和排除内容，保存当前会话草稿。未填写目的或未选择数据表时不能开始演示。
- **数据与文档**：选择数据库、Excel、CSV 合成表；添加合成 Markdown；分别配置待分类/数据说明/分析知识/混合，以及全局/多表范围。新文档用途默认为待分类（仅作探索提示），范围默认全局，演示中已有文档的显式范围保留。指定表但未选择表时拒绝保存。
- **发现过程**：启动或取消模拟运行，查看阶段进展、实际工具名称、合成 SQL 和守卫通过/拒绝示例。DISTINCT、组合查询和限量样本使用 `execute_readonly_sql`；层级专项核验由规则执行器承担。
- **元数据图**：显示表包含列和列间引用；按技术核验/语义候选筛选，点击表或列查看原始声明及独立的语义解释。
- **业务图**：查看已有合成实体及来源支持；切换根节点展示不同相对深度，实体 ID 不变。节点可以点击或用键盘选中。
- **运行记录**：分别显示模拟执行、发布和清理状态；取消后保留既有合成图，不产生本轮发布。

## 数据与验收边界

界面的表、文档、节点、SQL 和记录均由 `app.js` 内的合成数据生成。所谓“保存”仅修改 JavaScript 内存。刷新页面后恢复初始状态，不使用 localStorage、sessionStorage、IndexedDB、Service Worker 或文件写入。

“开始演示”推进的是预设状态，不执行 SQL、模型调用或真实发布。SQL 守卫界面只说明产品行为，不是客户端安全实现；正式执行必须由后端工具内部守卫、数据库权限及资源预算共同控制。

查询样本不展示、不进入日志、不作持久化。原型中的清理完成仅为状态演示，不能证明实际后端清理成功。正式系统应分别汇报发布状态和资源清理结果。

初始业务图非空，用于演示同项目增量工作方式。外部图谱导入及跨项目继承仅预留，不在此原型中实现。

## 文件

- `index.html`：入口，无外部依赖。
- `styles.css`：浅色工作台布局、响应式样式和图节点样式。
- `app.js`：页面状态、合成数据、图形和交互。所有状态只在页面内存中维护。

## 本轮验证（2026-10-20）

通过本地 HTTP 服务在 Chrome 与应用内浏览器操作，已检查：

- 分析目的为空时阻止启动，修改后可保存当前会话草稿。
- 新建文档默认为“待分类 + 全局”；选择指定表但未勾选时阻止保存；绑定两张表后显示完整来源标识。
- 元数据列节点可查看原声明和独立解释；关系筛选生效，两张图各自保留筛选状态。
- 业务图初始非空；切换根后“非付现调整项目”的深度从 1 变为 0，详情中的 `metric:noncash` 保持不变。
- 演示运行可完成或取消；记录分别显示模拟发布/未发布和模拟清理状态。
- 弹层可用 Escape 关闭；桌面和窄屏页面可浏览，窄屏图可横向滚动。
- Chrome 检查期间未捕获应用控制台 error。`node --check`、`git diff --check`、新增文档本地链接检查通过；静态检查未发现网络请求和浏览器持久化 API。
