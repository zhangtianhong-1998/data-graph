# 从列定义构建对象，并连接实际行中的对象

日期：2026-11-05。根据用户提供的脱敏目标、字段文档和运行反馈修订。未读取客户运行轨迹或事实数据，以下区分代码问题与待客户数据验证的解释。

## 问题判断

现有行映射从 `key_columns` 的值创建对象，`constant_properties` 只添加属性，不能把列名变成身份。指南将这个实现缺口要求为 unresolved，阻止了无依据的绕行，但也使有完整列定义证据的度量无法表达。这是映射能力缺口，不能靠用户每次在目标中授权“把数值列作键”解决；后一种做法实际会按金额去重，产生错误对象。

过滤能力并未缺少。Predicate 已有 `is_null`、`is_not_null`、比较和逻辑组合；模型可见的 schema 却只有任意 object，指南也没有语法说明。空编码应按明确范围处理，不应因少量缺失删除整个维度，更不应未经验证改用名称作身份。

跨源检查还有独立代码错误：工具的 `_max_bytes` 最多 64 KiB，用于返回模型的响应，却也传给本地 DISTINCT 匹配作为工作集预算。项目配置的 `max_working_bytes` 没有用于这次校验。因此不能仅从失败码断言“32 MiB 不够”，更不能把实例执行器的投影行数拿来解释另一处探查的内存耗用。

## 定义对象与事实对象

新增通用 `metadata_column` 映射：一个已经授权的物理列可以成为定义对象。对象类别仍由 Agent 根据本次目标、元数据和文档选择；不按 NUMERIC 类型、列名后缀或业务白名单自动认定度量。

身份由 `source_id/schema/table/column` 组成，明确区别于该列的事实值。声明名称、别名和语义属性需要已签发的适用元数据或文档证据。输出分别保留程序取得的目录类型/注释、Agent 据证据作出的声明和证据引用；不能把声明伪称为事实值。未知、未授权、被目标排除的列仍不允许建模，过期或其他表的引用不能支持该列。

列对象不要求表里存在数据行，也不扫描经营数值。多个表的同名列不会自动合并；本轮不新增跨列定义等价裁决或纯文档自由对象算子。行对象的身份和既有 YAML 保持兼容。

重复绑定同一物理列时合并兼容的来源支持、别名和属性，声明主名称或同一语义属性互相矛盾时要求修订。图的类型定义记录身份来源，跨草稿发布不能把行值恰好相同的四字段对象并入列定义对象。历史行图缺少该标记时按行身份解释；结构校验保留历史草稿的原始签名形状，新增默认字段不使旧预览失效。

## 关系需要分清依据

指标与维度仍用已有实际行配对或显式跨表查找。共现提供观测依据，关系含义、方向、身份范围和用户目标是否适用仍由 Agent 判断；不能把共现自动宣布成外键或业务真理。

新增行对象到列定义对象的端点映射，元数据端绑定该行来源表的具体列。另一端仍来自实际授权行键，可使用已有显式查找。只对实际存在的行对象形成关系，不用全图对象和列对象的两个独立集合做笛卡尔积。

- `schema_applies_to_rows`：文档或元数据解释该列对当前筛选范围的行对象适用；保留“声明的适用性 + 行存在”的证据性质。某行值为空不能单独否定定义适用性。
- `observed_non_null`：仅对该列非空的实际行形成观测关系；使用 SQL 非空过滤，不读取或输出金额值。不能据此宣称所有行或其他指标也适用。

元数据对象支持使用目录可见范围 `public`；事实关系继续使用输入行的原有 scope。查看范围不含 `public` 时沿用原有过滤，不擅自扩大可见范围。结构检查不执行事实查询；实例中的行关系必须完成对应投影检查。来源失败、字段匹配失败或数据冲突仍可使整份候选无法发布。

## 探查与收束

Skill 要求分别检查目标中的对象与关系覆盖。已经发现维度名称，不等于指标到维度的关系已构建；在 decisions 中记录了度量，不等于图中存在度量对象。Agent 应对目标相关关系提出候选、选择能区分解释的文档和实际配对证据，并记录具体未决原因，不预设所有对象两两相连。

用户提供的文档也有可疑之处，例如部分编码/名称描述互换、币种名称与列名不一致、创建和更新时间说明混淆。这些是需要核对的线索。程序不替模型按列名自动修正文档，也不把相同取值范围标记当作定义等价证明。

显式 `is_not_null` 保留空字符串；若证据说明空字符串也表示缺失，再用 `all` 联合 `ne: ''`。实体和相关行配对要采用一致范围，筛选条件保留在验证和来源信息中。避免为通过检查而静默过滤冲突样本。

## 内存边界与验收

跨源检查使用项目的本地工作集上限；返回模型的行、统计和响应仍保持独立小窗口。只投影所请求的匹配键及显式消歧列，避免携带无关名称和路径。超限返回限额、估计工作集及失败来源/阶段，不返回源值，也不将未完成计数标成完整。

验收使用脱离客户名称的合成字段与空表，检查：列对象不查询数值、列名变更后显式映射可运行；未知/越权/错表/过期证据拒绝；NULL 和空字符串范围准确；行到列关系两种依据各自正确；跨表实际查找成立；数千键超过 64 KiB 响应窗口仍能按工作集完成检查；真正超限保持未决。再用实际 Harness 和本地脚本模型走工具与发布，不把它称为真实模型发现质量验收。
