# 请求失败与任务结果分开处理

`full-extraction-v2-submission-state-20261103T011934Z` 中，两次 JSON 解析失败进入格式修订后，因原内容不可比较而再次失败。不可解析的响应没有形成可采纳提案，不应被当作必须保留语义的修订基准。

## 请求层

非法 JSON、损坏的响应结构和可重试的传输错误，按原上下文重试当前请求。普通 Agent 回合保留工具列表、工具结果、已保留草案和证据；坏响应不回放，也不执行其中的工具调用。

已能解析、但字段不符合 schema 的对象继续按受限字段修订。有效兄弟提案、排除条件和已有否定审查仍需保留。修订请求发生网络或 JSON 错误时，重试同一个修订请求，不丢弃原有约束。

`allow_schema_repair=False` 只禁止内容修订，不再同时关闭传输及语法错误重试。请求重试与字段修订共享原有 `retries` 上限；当前默认值仍为 1，即一次请求最多发送两次。所有发送计入模型调用和运行时间额度。没有无限重试，也没有放宽解析或发布条件。

## 任务层

请求重试成功后，Agent 继续当前调查。请求失败次数和诊断作为过程记录，不产生任务级待办。

重试用尽、全局额度耗尽或其他未恢复错误确实中断调查时，仅对应任务保持 `deferred`。已经验证的规则继续执行和发布。字段全部覆盖不代表调查已结束，不能据此清除中断状态或写入错误的完成缓存；续跑只重新调查未完成的表。

## 运行与报告

运行状态按最终任务与发布结果汇总。已恢复的请求失败不使运行变成 `PARTIAL`；仍有中断任务时保留未完成状态，同时保留已发布图谱。

新增三个计数：`request_retry_attempts` 为实际追加请求数，`request_retry_succeeded` 为经请求重试恢复的逻辑请求数，`request_retry_exhausted` 为用尽重试额度的逻辑请求数。前端分别展示这些数字。无法建立比较依据使用 `comparison_unavailable`，不再错误标为 `meaning_changed`。

## 验证边界

使用离线接口回包验证：合法草案后出现坏 JSON，再正常结束，身份范围、属性、排除列和证据均保留；连续坏 JSON 只影响相关调查，其他规则继续发布；续跑只恢复受影响表；全局调用额度不能被重试绕过。真实模型效果需要后续实验验证，历史实验文件不改写。

本地验证：后端全套 2,443 项通过；前端 184 项通过，类型检查和构建通过。
