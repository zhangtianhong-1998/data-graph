# 只读预检恢复、配置保留与图谱续传

日期：2026-11-10。以 `0dfa6fd` 为基线，依据用户转述和本地故障注入修改。未取得 Test4 原始日志，未连接客户数据库。本文更新此前“只读资格失败一律不重试”的约定。

## 1. 失败会话不能使用，但可以重新检查新会话

`_start_readonly(stage='connection_preflight')` 已给读回失败附上 `qualification` 诊断，但保留独立错误码 `read_only_transaction_unverified`。原 `_preflight_can_recover` 先按外层错误码过滤，随后也只接受参数绑定和 DISTINCT，导致换新会话时的只读预检失败零次重试即停止来源。此前限制扩大了安全边界：禁止使用不合格连接，不等于禁止丢弃它并检查另一条连接。

现在已取得来源授权后的快照边界，允许如下路径：

1. 换新会话，在 `connection_preflight` 检查只读资格、参数绑定及 DISTINCT。
2. 读回为空、形状不符或值不符合要求时，关闭该会话；安全诊断记录检查项目和失败类型，不记录凭据或原始读回值。
3. 在既有三次共享恢复额度内退避换连接，重新检查全部能力、只读、目录和授权；通过后才允许事实查询。
4. 持续失败则停止该来源、保留草稿。次数不由模型决定，也不因换错误码清零。

首次创建来源仍必须完成资格检查；已经合格的会话在 `snapshot_start` 读回不符合只读要求，仍不能按这条预检路径恢复。认证、权限、目录变化、取消及预算限制保持原约束。已返回部分事实数据的事务不重放。错误外层变成 `database_reconnect_failed` 后，离线列定义发布仍检查内部只读资格失败，不能借包装错误绕过目录资格要求。

数据库仍按完整只读快照使用，用后释放。此次没有改回长驻连接，也没有把同一快照中多条查询拆成多个事务。

## 2. 配置与声明缓存独立于运行目录

保存连接信息的底层机制已存在。页面消失有两条实际路径：浏览器会话恢复失败连带清空项目状态；元数据只存放在当前运行输出目录，从零运行切换目录后读不到旧声明。显式刷新失败还会使目录标记失效。

新增项目内 `metadata/catalog-preview.yaml`，只存表列声明和版本上下文，不复制事实行、业务图或凭据。成功刷新后保存；旧工程在读取有效目录或开始从零运行前迁移，不扫描历史实验。

- 页面 GET 不连接数据库，可从匹配的项目缓存显示表结构及 YAML。
- 显式刷新失败保留上次成功内容，显示 `refresh_failed`，不将它冒充本次刷新结果。
- 局部刷新按每个来源的授权、凭据修订与文件版本保留未变化来源；新增来源不会抹掉已有来源。
- 权限、凭据修订或文件变化后，不显示失效声明。缓存不是执行授权，构图仍执行自己的来源检查。
- 浏览器凭据恢复与项目内容读取分别处理，恢复失败显示提示，不隐藏连接列表；密码不在列表明文展示。
- 可选的 GET 缓存副本写入失败只产生安全警告，已读取的有效声明仍可显示。显式刷新或从零运行前的必要迁移写失败则报错；从零运行不切换目录、不启动 Worker。路径安全检查不能被这些处理吞掉。

兼容边界：旧工程若早已切换目录，当前无成功目录且从未生成项目缓存，需要显式刷新一次；不凭历史文件名推断哪个目录仍获授权。

## 3. 图谱加载保持完整，同时控制每批大小

原实现已有节点/边分批、圆形 Canvas、暂停及续传。每批最多 1000 条不是整图上限。新增修复针对两个问题：一批数量不多但属性巨大；坏页尚未完整校验就修改已接收状态，导致续传游标和节点集合不一致。

后端初始业务图、批次和聚焦邻域按实际内容限制节点/边响应，约 1 MiB 一批。单项超过 32 KiB 时提供带 `overview_only` / `detail_fields_deferred` 标记的概览，不缩短身份及关系端点；完整内容仍在发布物和详情接口中。两跳初始页优先保留中心及连接路径，不为凑数量返回断开的邻居。页游标按实际返回数量推进，不按固定 1000 跳过记录。

前端在临时集合中验证整页、端点、重复记录、版本与总数，全部通过才更新画布和游标。临时网络错误、超时或 HTTP 502/503/504 在同一游标最多自动重试两次；继续失败则保留已接收批次并显示“重试加载”。“重新加载全图”才清空当前传输。取消、权限或发布版本改变不走自动重试。

边界：上述大小上限针对批次节点/边内容，不含类型词汇表等响应外围信息。初次读取仍载入发布 YAML、重建授权视图，详情仍需按对象读取完整属性。这次没有改成磁盘流式图存储，也不承诺无限节点规模。
