### 在同一批检查点上并行核对三件事

1. **找出可以在哪个阶段修的键。** 用 `scripts/audit_checkpoint_merge.py <C 模型审查运行.json> --node merge_1 --recheck-proposals-only` 复核已进入历史裁决的提议。输出的 `cross_table_check_summary` 按是否共享已绑定的键章节、首项观测检查及整单元授权指纹是否相符交叉计数。没有章节且另外两项通过，是仅在这三项上缺章节的键检查数；同一键出现在两个提议会计两次。章节是否肯定共享身份须另读原文。没有提议、被截断、名称不合、同表同列或同表跨轴的项分别用审查表和逐模式明细对账。
2. **核对“拨备”和收入类。** 对每个要比较的运行，执行 `scripts/audit_checkpoint_merge.py <运行.json> --node merge_1 --include-edge-lineage --explain-name 拨备 --explain-name 拨备13 --explain-name 坏账准备 --explain-name 净销售收入 --explain-name 专业服务收入`。多名称共用一次审计。按单元、草稿、来源表列、带类型的完整键、实际观测名及最终输出 ID 对账。查清“4×23 份输入”与“24 个双份组加 1 个单份组”的分组维度和成员映射。每组核实同物理键、跨表同目录、异轴、口径冲突或待定。对同一节点命中多个名称的情形按 ID 去重。
3. **核对变少的原始边。** 将旧批次和 C 映到同一冻结来源上；边 ID 可以不同，用源身份与快照、原始行或有等效证据的明细键、有向端点列和值、关系断言及适用范围核对。先报有共同来源覆盖的事实数，然后逐项区分同事实多种建模、同码延续策略、覆盖新增/退出、原来支持但 C 漏抽、无法定位。另报 C 新增的无支持事实。核对两个不同业务事实之间即使端点相同也能分别查回。缺少快照或行见证的部分记“无法核实”。4,383 是边数的**净差**，要分别列少了多少、多了多少；2,043 个旧自环也不能直接从净差中扣作已证重复。

### 何时重新抽取

| 现场证据 | 该运行什么 |
| --- | --- |
| 正确观测已在 C 检查点，但未入候选、回复截断、验证或应用时误拒 | 重跑相应的合并实验，可固定模型提议单测验证器。 |
| 原始材料有依据，检查点缺少决定身份或关系的字段、列绑定、适用版本或行见证 | 冻结同批来源，只重抽受影响分支。对比草稿修订前后及签入产物的依据；用同一组新检查点再比较两种合并。 |
| 原始材料也没有说明两个轴是否共用身份 | 记待定并列出缺少的业务依据。重抽同一批材料不会补出业务事实。 |
| 修改了所有分支共用的抽取契约，且下面的正反对照已通过 | 在冻结源上做一次从四分支抽取到合并、发布和查询的完整验收。先等抽取终态，再复用这同四份新产物比较两种合并。同源对照仅切换待测机制；模型版本或读取窗口变化时单列。 |
