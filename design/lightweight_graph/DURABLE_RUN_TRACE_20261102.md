# 本地运行轨迹与模型额度

用户要求保留可排查的完整执行过程，并由用户决定何时清理。这改变了原来默认不保存模型会话和查询结果的约定；查询权限、图谱发布校验、凭据保护继续有效。

## 模型配置

工作台“Agent 与模型”提供探索轮数（`max_discovery_steps`，默认 16，范围 1～32）、最大输入 tokens（`max_prompt_tokens`）、最大输出 tokens（`max_output_tokens`）和接口超时秒数（`timeout_seconds`）。独立 Agent 文件也可以调整这些值：保存时新建一个项目内的 Agent 文件版本并切换引用，旧文件保留。

保存成功后，下一次启动立即读取最新配置，无需重启服务。“保存并开始抽取”先完成配置保存，再携带最新修订号启动；保存失败时不启动。正在运行的任务使用启动时的配置，运行中不允许修改。完整轨迹的 `run_configuration.effective_model` 记录该次任务实际采用的模型参数，可用于核对。

输入预检和历史裁剪使用同一 token 估算方法。未知服务的分词器无法在本地精确复现，因此预检明确标为估算；调用后的用量优先采用服务返回的 `usage`。中文、英文和 JSON 的比例不同，不能统一按四字符一个 token 计数。设置 `context_window_tokens` 时，总窗口还要预留最大输出空间。

`max_prompt_bytes`、`max_response_bytes` 是可选的传输保护，默认 `null`。旧配置里显式填写的值仍有效，前端会显示，并可由用户取消。SQL 返回量、进程工作内存、HTTP 请求体大小等仍按 bytes 计量，它们不是模型上下文额度。

## 记录内容与位置

`record_trace` 默认 `true`。按时间顺序记录本次配置、实际发送的模型消息与工具 schema、接口响应、解析前正文、失败与重试、上下文裁剪、工具参数及结果、Agent 开始与结束、流程阶段和最终报告。只记录实际可获得的内容，不声称能记录服务端未返回的内部推理。

- 工作台：`<project>/runs/<run_id>.trace.jsonl`。
- 命令行：`<output>/traces/run_<unique_id>.trace.jsonl`；结束事件中带报告的运行编号。
- `.trace.index.jsonl` 记录每个完整事件的文件位置，页面无需反复扫描大文本。
- `.trace.status.json` 标记写入故障。未完成的一行不冒充完整事件。

文件保存在本地，不上传外部追踪平台；API key、Authorization、数据库连接凭据及注册的秘密值脱敏。轨迹可能包含业务样本、SQL 和文档内容。它与图谱事实隔离，也不会被下一次 Agent 自动当作已验证知识。`record_trace: false` 关闭后续记录，不删除已经存在的记录。

## 查看、导出和清理

运行详情中的“运行轨迹”按页展示事件，展开后可看完整输入输出。导出 JSONL 不受页面分页限制；运行中导出是截至请求时已完整写入的快照。发生写入失败或终止时遗留未完成记录，界面标为不完整，不会因此否决已验证图谱。

结束运行仍会关闭数据库连接、清空临时内存、释放锁。这些是资源释放，不是删除历史。新运行和服务重启不会清理过去的轨迹、报告或 worker 结果。

“清理轨迹”需要用户主动确认，运行中不可执行。接口校验项目、运行编号与配置修订，只清理该运行的轨迹及索引，不删除报告、上传文件或已发布图谱。历史运行如果没有记录过原始输入，无法从计数报告还原。

## 验证范围

固定回归覆盖实际模型请求、坏 JSON 后重试、流式/非流式响应、SQL 工具输入输出、长文本、脱敏、索引一致性、写入失败、项目隔离、手动清理及独立 Agent 文件配置。工程测试不代表真实客户数据上的抽取质量已经通过。
