# 累计返回量、验证完成状态与连接恢复

本次依据用户提供的另一台电脑运行摘要核对源码，没有客户数据库、原始 trace 或该电脑的完整代码差异。当前本地基线为 `4f1f070`；一次远端获取因网络连接失败，不能宣称已审查另一台电脑所有修改。

## 已确认的问题

项目可设置 `max_working_bytes`，但 `open_sources` 创建的 `QueryBudget` 原先只接收查询次数与总时限。累计返回行数和字节数一直采用适配器默认值 400,000 行、64 MiB，无法从项目配置调整。将工作内存改成 1 GiB 不会改变这两项限制。

返回量按游标实际取出的行累计，包含元数据、探查及实例验证中经过预算包装的查询。字节数采用规范化行的估算大小，不是磁盘占用、实际网络流量、Python RSS、MCP 响应或模型 token。释放批次、缓存或图谱内存，不会退回累计用量；重复查询会再次计费。因此不能仅用“上一轮分批发布”解释上一轮为何未耗尽，必须比较实际读取范围、投影复用和整轮用量。

原来的错误建议还存在优先级缺口：同时有名称冲突和累计返回量耗尽时，`failure_guidance` 可能返回名称冲突处理建议。发布检查仍会拒绝不完整验证，但 Agent 容易据此再尝试发布。返回量耗尽现在优先按资源中断处理，明确提示不完整验证不可用于隔离发布。

## 配置、执行与反馈

新增两个顶层字段：

| 字段 | 默认值 | 含义 |
| --- | ---: | --- |
| `max_returned_rows` | 400000 | 整轮所有来源累计返回行数；正整数，`null` 表示不限 |
| `max_returned_bytes` | 67108864 | 整轮累计返回的估算字节；正整数，`null` 表示不限 |
| `max_working_bytes` | 33554432 | 原有构图工作集限额，仍单独生效 |

前端直接填写累计行数、累计返回 MiB 和构图工作内存 MiB。两项累计额度可分别选择不限；1 GiB 对应页面中的 1024 MiB。保存、刷新、完整配置合并和独立模型配置文件都使用同一项目值。未设置的新字段保留原默认值，已有显式配置不自动改大。保存后下一次运行读取新值，运行中不更换预算。

所有来源共用项目预算。接入外部已准备好的适配器时，导入已有计数、最早截止时间及取消状态，同一个旧预算只导入一次。不能借切换来源、草稿或阶段清零。累计限额取消后仍记账；只读授权、单查询结果限制、查询超时、工作内存和整轮时限继续生效。

工具返回与最终报告增加 `query_budget`，包含实际限额、已使用和剩余值；耗尽诊断还记录对应配置字段。Agent 在探索和验证前能看到额度。额度已超限后，新查询直接拒绝，不再继续发去重计数或下一个映射。构图 Skill 明确区分累计量与驻留内存，禁止靠删维度、度量或路径信息掩盖资源缺口。

## 发布与历史

仅有名称冲突、且数据读取已经完整结束时，可继续使用现有冲突隔离发布。只要同一次验证还包含返回量耗尽、截断或读取中断，就不具备这项发布资格。诊断已生成不等于完整验证成功；草稿和已保存证据保留，其他独立完成的验证仍可发布。

调整资源额度不改变目标或来源指纹；新运行可以复用草稿，但必须重新完整验证。修改目标或授权后，旧验证不能直接充当新目标成果；旧历史仍保留。当前画布没有旧节点不能单独证明旧文件已删除。

## 连接恢复的边界

当前代码在一次去重计数与对应完整投影的快照结束后释放连接；模型思考期间不长期占用它。`connection_generation` 增至 136 表示发生过多次物理会话轮换，不能由整轮两小时推断同一连接存活两小时。

新建连接已能对未知建连失败进行有界恢复。本轮补上资格预检阶段的窄缺口：新会话尚未产出事实行，`database_preflight_failed` 在 `connection_preflight` 阶段未能分类时，允许消耗现有的最多三次恢复额度。认证、权限、目录变化、能力绑定错误、取消与预算耗尽仍不得借重连绕过；已输出部分数据的查询不自动重放。

Gauss 默认增加 libpq TCP 保活参数，显式 DSN 配置优先。保活只是连接存活探测，实际行为受操作系统、libpq 和网络影响；不能保证 60 秒内发现所有故障，也不能保证错误变成某个分类或永不熔断。重连仍须重新检查权限、目录和只读能力。[libpq 官方参数说明](https://www.postgresql.org/docs/18/libpq-connect.html#LIBPQ-PARAMKEYWORDS)也明确说明这些参数有平台支持条件，Unix-domain socket 不使用 TCP 保活。

## 验证结果

回归覆盖有限/不限配置、保存后重载及启动参数、跨来源共享与去重计费、分批后累计不退回、停止后的新查询拒绝、预算与名称冲突同时出现时的提示和发布拒绝，以及调额新运行复用草稿后完成隔离发布。连接使用驱动替身验证未知预检失败恢复、确定性错误不重试、已有 DSN 保活参数保留及恢复次数上限。

最终后端 **3,253 项通过**（212.10 秒，启用实际 Harness 与本地脚本模型）；上一轮已通过的 310 秒默认 fetch 测试未纳入本轮命令，其传输实现未修改。前端 **359 项通过**，TypeScript 检查、生产构建和差异空白检查通过。首轮发现静态配置 Schema 漏同步，已补齐后完整复跑。

本地验证不能证明客户数据库连接已稳定，也不能保证 1 GiB 能满足所有草稿。现场应核对新运行的生效配置、累计用量、验证读取完整性和实际发布的实体/关系类型。
