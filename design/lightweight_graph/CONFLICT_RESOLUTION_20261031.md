# 发现冲突的修订与独立发布

## 本轮依据

最近完成的 `full-extraction-v2-schema-first-20261031T024424Z` 为 PARTIAL：64 次调用、3,149,520 tokens、约 58 分 20 秒，仅发布产品定义的一条规则，得到 5 个业务节点、0 条业务边。18 次无效提交、4 次待完成提交，语义修订与引用补正均为 0。模型额度没有用尽。

本轮结合用户意见、Cursor 复核和代码检查，处理三处问题：字段认识没有替代生命周期；编译冲突不能形成可恢复的修订任务；图级失败归因和发布范围过大。五个单位置字段候选与一个五位置对象候选同时存在，说明当前认识冗余，不能据此断言系统已确认五种实体，也不能据此解释全部发现失败。旧运行未保存渠道冲突双方的结构，因此无法还原具体差异。

## 修改约定

1. **显式替代字段候选。** 新认识用 `supersedes_object_ids` 指明取代哪些旧候选。仅同来源、同依赖版本的元数据启发式候选可被替代，必须承接编码、名称、英文名、别名、层位和范围。旧记录保留历史及替代关系，退出当前提示和候选索引。列重叠本身不能触发删除；候选不能覆盖已验证规则。
2. **先合并兼容属性，再处理真正矛盾。** 按编译后的逻辑规则身份比较提案，不依赖 Agent 自选的组名。身份、范围、层级和语义义务一致时，合并兼容属性并重新验证。有矛盾时保留双方安全结构、字段差异和引用，允许一次有界补查与修订；原样提案和相同证据不重复裁决。
3. **候选可以恢复。** 保存授权列映射、规则策略、失败类别和依赖版本。后续会话可读取原结构与差异，重新查询和验证。原始行、完整对话、SQL 常量和任意推理文本不进入结果库。来源授权、schema、目标或文档变化后，旧候选不得直接复用。
4. **审查协议与语义结论分开。** 格式修复只改变明确无歧义的表达，已有反驳、未决和条件不能被改成支持。补查材料默认使用列引用、计数和完整性；必要的名称或定义只在授权会话内临时读取。修复后的方案仍需独立审查及全量执行检查。
5. **失败只影响实际依赖组。** 先定位冲突事实及贡献规则，再按共享身份、引用和层级约束分组。每条规则的完整代次不可拆开。独立有效组可继续发布；冲突组保留待修任务。每组仍与存续图联合验证，保留 CAS 和原子发布。不能因同一次运行或同一张表就合成一组，也不能无故隐藏无关旧规则。

## 验证要求

- 五个字段候选被一个五位置模型显式替代，英文名及层位映射保留，旧候选退出当前认识；不兼容替代不改变旧状态。
- 渠道的两个兼容提案合并属性，身份不变；编码误作名称时能得到具体映射反馈并修订。
- 审查输出协议错误有有界处理，反驳和未决不得转为支持。
- A/B 的共享冲突保留待修，独立 C 发布；引用撤回与跨规则层级环仍受完整检查。
- 重启可读到安全候选；授权或依赖版本变化后不复用旧结论；结果库不包含探查行或模型任意文本。
