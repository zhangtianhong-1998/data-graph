# 抽取目标与发现 Agent

更新日期：2026-10-19。本文说明本次代码改造：发现阶段使用目标配置、模型工具循环和程序验证。原有身份、支持账本、发布与不保存源数据的约束继续有效。真实 Gauss 和模型服务的环境验收尚未执行。

## 运行过程

1. 读取授权目录、目标配置和适用的数据说明文档。目标在模型第一次调用前进入系统上下文；源元数据和文档作为证据，不获得指令权限。
2. Agent 结合目标提出列组、角色或关联假设，选择统计工具或编写只读 SQL。已启用模型的路径不以列名正则筛出所有候选；原有确定性发现保留在模型关闭时使用。
3. 工具验证请求、执行查询，返回有上限的临时观察。Agent 根据结果继续探查、修订或弃权，最后提交结构化提案。
4. 程序检查提案中的列、类型、输出角色和目标范围，编译为 RuleSpec。正式发布前仍执行完整规则验证，不能把工具中的少量样本当作全范围证明。
5. 通过验证后，由程序执行必要列的联合去重、层级处理和关系构建；新增数据符合规则时，不逐行调用模型。

## 目标配置

运行配置的 `goal` 支持以下字段：

| 字段 | 用途 |
| --- | --- |
| `purpose` | 本次构图目的 |
| `include` / `exclude` | 文字描述的关注对象与排除内容 |
| `discovery_guidance` | 如何选择证据、推进探查的指引 |
| `entity_kinds` / `relation_kinds` | 输出允许的实体和关系类型，程序检查 |
| `source_scope` | 目标覆盖的来源、schema 或表，不能扩大授权 |
| `excluded_columns` | 禁止查询和投影的列 |
| `evidence_only_columns` | 允许辅助探查，但值不能形成实体键、名称、属性或关系端点 |
| `observation_values` | 默认关闭具体业务观测值入图 |

这些字段不是客户数据集映射表。可以仅描述“构建经营指标分析图”，再让 Agent 根据元数据、统计、样本和文档识别具体列。名称正则可提供线索，不能替代业务判断。数值列的名称、单位和公式可能定义一个指标；排除每行金额不应同时排除这些定义信息。

文字指引本身不提供任意业务概念的确定性识别保证。类型、列范围和已标注的输出角色由程序检查；需要业务语义判断的内容仍须依赖有效证据，结果应保留未决项。全部目标字段进入发现依赖摘要。目标、发现模式或工作流版本改变时，旧解释先失效并保留历史，再重新发现；没有替代规则时也不继续复用旧目标的结果。

Agent 提案覆盖实体列组、显式属性角色、宽层级、父编码长层级，以及列名不同的跨表端点映射。FD 反例触发的新会话携带原规则结构与冲突计数。独立文档支持的共享定义策略、JSON 引用和判别分区验证继续复用；模型不能自行生成未经注册的分区常量。

## Agent 工具

| 工具 | 返回内容与边界 |
| --- | --- |
| `get_metadata` | 目标与权限范围内的表、列和已读取约束 |
| `search_knowledge` | 适用的数据说明文档；分析知识仍按独立文档流程抽取 |
| `profile_columns` | 指定列的基础统计 |
| `check_fd` | 检查指定列组的函数依赖 |
| `check_reference` | 检查跨表列组的结构引用 |
| `execute_readonly_sql` | 执行工具白名单内的只读查询和绑定参数 |

工具返回值仅是探查证据。普通查询结果注明返回范围和是否截断；统计检查通过也不能自动证明业务含义。每次工具最多返回 128 行，实际还受源配置、响应字节与内存预算限制。`metadata_only` 模式禁用 Agent 的实例查询工具，包括聚合查询；它不将聚合结果冒充元数据发送给模型。

SQL 工具只接受严格校验的单条查询：允许的 SELECT、非递归 CTE、UNION/INTERSECT、显式列投影、固定函数和受限等值关联。COUNT(*) 可用，SELECT * 不可用。多语句、写操作、未知函数、递归 CTE、CROSS JOIN、OFFSET、越权表列以及不在语法白名单中的形状被整体拒绝。工具不通过删掉危险关键词修改 SQL。

同一请求在工具和适配器执行处都受检查。模型不能提供数据库凭证或修改白名单。行级隔离必须由部署账号、授权视图或数据库行策略保证；本轮没有实现多租户授权服务。`goal.source_scope` 只是业务范围，不能替代数据库权限。

## 预算、保留与验证

`model.max_discovery_steps` 默认 8，最多 32；`model.max_tool_calls` 默认 16，最多 64。它们限制一次探索，整次运行还受调用/token、查询次数、内存和截止时间限制。达到上限应报告缺口，不将尚未完成的探索声明为成功。

LIMIT 只限制返回量。聚合、去重和 JOIN 可能扫描大量来源数据；工具返回量小不等于扫描成本小。没有实际扫描统计时明确记为未知，不将其填为零。真实数据库的只读事务、超时与取消需要在客户产品和版本上验证。

SQL、参数、工具返回行和 Agent 对话只保存在本次运行内存；不写入日志、会话存档或检查点。持久化仅使用原有白名单，保存规则、元数据、批准的图事实和安全计数。模型厂商及数据库自身的日志保留由部署验收确认，本地合成测试不能覆盖。

本轮测试应覆盖：模型根据查询结果继续调用工具、非标准列名的发现、目标指引生效、禁查列和仅证据列约束、危险 SQL 被拒且未执行、工具及模型上限、metadata_only 隔离、返回值不进入持久化。模拟服务验证调用协议与程序行为，真实语义效果需要另行评测。
