# 图身份与发布存储实现

源码位于 `src/lightgraph/identity/` 和 `src/lightgraph/store/`。结果库使用 SQLite，数据库检索得到的原始行、样本、模型请求和响应不进入这些接口。

## 已实现的行为

- **稳定身份**：来源编码作为本地查找键；经验证的完整定义可以跨租户共享。名称、单位或分类体系单独相同不会触发归并。名称修订保留实体 ID，定义变化生成新的绑定修订，历史发布仍指向原实体。
- **身份策略修订**：共享依据新增、撤回或迁移到另一语义注册表时，同步创建绑定修订。恢复历史定义和策略会复用已有实体 ID；失败暂存不会使下一次恢复运行生成新实体。已发布图仍通过依赖集合原子切换。
- **事实与支持分开**：节点存在、每个属性值、边和文档主张各有事实 ID。来源、规则修订、范围和分区进入支持 ID。多个来源可以支持同一事实，重复运行不增加重复节点或别名。
- **按属性授权**：`view`、`search`、`export` 先按调用者范围筛选支持，再生成名称、别名和属性。没有可见名称时显示实体 ID。候选支持不会借用另一个范围的确认状态。
- **原子发布**：只有完整、一致、依赖有效且未截断的分区可以切换 head。分区以逻辑规则 ID 和分区定位，generation CAS 拒绝旧任务覆盖新结果。暂存结果不进入查询或导出。
- **精确撤回**：新分区支持集合替换旧集合，其他来源继续有效。A 独有的别名随 A 支持撤回；B 支持的共享节点保留。边和属性的端点检查会阻止不完整的依赖变更。
- **依赖集合提交**：`publish_partitions` 可以一起替换相关分区。同一来源绑定的身份变更要求相关结果一起迁移，或先使旧依赖结果失效。
- **历史与水位**：历史支持保留当时的验证引用、文档定位和绑定版本。源窗口的所有声明分区完成后才推进水位，后面的窗口不能跳过未完成的前序窗口。
- **持久化约束**：图属性、关系、关系端点类别、主张模态和规则算子参数均有白名单；拒绝未知字段、原始结果集、样本及请求正文。错误只使用固定代码。

## 主要接口

```python
store = GraphStore("output/graph.sqlite")
identity = store.identity.resolve(
    kind="Metric", source_ref="source.schema.table", namespace="tenant-A",
    business_key="2150", definition={"definition": "已核验的指标定义", "unit": "元"},
    shared_verified=True,
)
publication = store.begin_publication("registry", 1, "partition-A", {"schema": "schema-v1"})
store.stage_fact(publication, graph_fact, support_spec)
store.publish_partition(partition_completion)
view = store.view({"tenant-A"}, domain="default")
```

`shared_verified=True` 表示上游已验证共享依据，不能仅因列名或名称相似而设置。`SupportSpec.binding_revision` 必须与本次实体解析结果一致。规则和验证记录分别调用 `put_rule`、`put_validation`；同一规则修订的定义不可覆盖。

`prepare_rule_rollback` 只验证旧规则与当前依赖是否兼容并登记回退请求。发布回退结果需要按当前数据重新执行规则；该接口不会把历史图直接改成当前图。

## 验证与边界

运行存储专项测试：

```bash
.venv/bin/python -m pytest src/lightgraph/tests/test_graph_store.py -q
```

当前专项测试覆盖共享引用与属性撤回、跨规则去重、候选状态隔离、关系端点类型、历史证据、身份版本、发布 CAS、事务故障、依赖集合提交和窗口水位。这些测试使用合成图事实与 SQLite；真实 Gauss 一致性和部署环境的数据保留审计需要单独验证。

规则执行测试位于 `src/lightgraph/tests/test_rules_engine.py`。它验证源事务退出失败时不发布、失败规则不留下确认状态、连续层级填充与跨层编码冲突、单侧 JSON 数组引用的完整校验，以及连续运行和删除时实体与引用关系一起更新。规则和文档依赖未变时，可复用规则并重新读取关键列；测试中的第二、三轮运行禁止模型调用。

规则可按 `scope.partition_by` 执行：完整枚举和所有分区读取共享一次源快照，每个分区分别受返回行数限制。只有整条规则完成后，才一起提交新分区与已消失分区的空替换；枚举超限、中断、后续分区失败或源事务退出失败均保留旧发布。分区值与临时谓词只留内存，结果库只保存逻辑分区引用。首版要求分区列属于实体键；层级规则的分区列还必须属于命名空间，避免把同一实体或树结构切开。默认最多枚举 256 个分区，可通过执行器参数调整。

存储层接受上游签发的分区完成记录，不能自行证明源端读取完整或业务含义正确。访问范围由调用方认证后传入，当前模块不提供身份认证服务。SQLite 文件本身应只对运行服务和授权管理员开放；文件读权限不等于图查询范围权限。

历史发布保留的是抽取结果与支持版本。源数据没有历史读取能力时，无法据此恢复过去的原始单元格。持久化字段白名单也不能代替源查询、模型 SDK、日志、临时文件和操作系统层面的留存检查。
